# Architecture

## Product contract

SI exposes one macOS input source. Settings contain a set of enabled languages, not an active language. Every enabled provider is queried for the current composition. Matching candidates coexist; ambiguity is a choice for the user rather than a reason to switch modes. Literal input is always offered.

## Data flow

```text
Host application key event
  → SIInputController
  → client-local InputSession and immutable CandidateRequest
  → full/provisional background workers
  → CandidateEngine
  → Swift ChineseDecoder + English lookup + shared English/mixed lexical search
  → language-aware merge by shared effective score + exact literal fallback
  → revision-checked CandidateResult → InputSession
  → client-local selection/page state → nonactivating AppKit candidate window
  → committed text in the host application
```

## Interface localization

`mac/SI/Localization/Resources/{en,zh-Hans}.lproj/Localizable.strings` provides the same English source keys and Simplified Chinese translations to SwiftUI and AppKit. The app uses the main bundle and native macOS app-language negotiation, with `en` as its development language. SwiftUI literal labels use native localization; `L10n` resolves dynamic labels, errors and format arguments. The package builds the same helper/resources as `SILocalization`, using `Bundle.module` for tests. Language changes take effect on a normal process restart; no extra language preference, input mode or keystroke shortcut is introduced.

Localization stays outside `SICore`. Stable language identifiers, core display-name/label metadata, candidate identity, ordering and exact commit bytes are unchanged. Settings localizes the core language/punctuation descriptions at presentation; `CandidateDescription` derives localized candidate labels from structured metadata. User text, phrase codes, application names/identifiers and archive contents are never treated as translation keys. E/C/A punctuation badges keep their existing identifiers while tooltips and accessibility descriptions are translated. No input or personal data is added to localization resources.

## Chinese engine migration

The current worktree replaces production Chinese decoding with a native Swift adaptation of MSIME. Debug and Release builds pass after the first validation round; regression and quality failures remain documented in `docs/VERIFICATION.md`. It has not been profiled in host apps. `docs/IMPLEMENTATION_PLAN.md` records remaining correction-path, optional neural and quality-parity work. No Rust library, foreign session state, user journal, network inference or telemetry is linked.

`PinyinDecoder` is the shared facade for app and package. Production and injected Chinese lexicons feed the same `ChineseDecoder`. `ChineseSyllables` derives the primary minimum-segment cut and bounded complete alternatives from the pinned syllable inventory; explicit apostrophes constrain cuts. Canonical umlaut aliases are applied per syllable. Existing `PinyinInput` maps normalized letters back to exact source-character boundaries, including ü, u: and trailing separators.

`ChineseLexicon` performs exact, trailing-prefix, mixed-initial and longer-word lookup over one read-only SQLite resource. Injected lexicons implement the same lookup in memory. Chinese and English use the same versioned SQLite schema, weight metadata and `LexiconDatabase` reader. The database and prepared statements are protected by one lock; this explicitly documented synchronization is the basis for the database wrapper's sendability, independently of InputMethodKit callback assumptions. The immutable SQLite URI avoids journal writes and file-version polling. Statement lifetime never escapes the lock. Resource initialization is lazy on candidate workers, not performed by constructing a deferred client session.

`ChineseResources` resolves the same bundled resources in the Swift package and application. `ChineseNgramTable` maps validated MSNG v1 tables, builds immutable hash-key buckets once, and supplies word bigram/trigram increments without per-event model initialization. The source snapshots, revisions, checksums, SI additions/exclusions overlay and data-generation entry point are documented in `Data/Chinese/MSIME/README.md`. The public overlay excludes the retained source's 85 private-use character readings during generation, so neither direct lookup nor composed paths can use them from the bundled dictionary. No runtime download path exists.

The Chinese lattice spans syllable positions, with up to seven syllables and 32 lexical rows per span. For an uncorrected complete primary reading, up to 32 complete cuts with the same minimum syllable count share this lattice, including inputs longer than four syllables and cuts constrained by apostrophes. This bounds complete segmentation alternatives without rewarding extra syllables. Each edge and path carries exact normalized-source offsets: only matching offsets can join, repeated spans are looked up once, and prefix scoring/confirmation uses each path's actual source boundary. Minimum-cut dynamic programming runs before bounded enumeration so longer cuts cannot exhaust the 32-cut budget. Corrected aliases and incomplete readings retain their primary-only sentence behavior. Saved personal codes can add independently bounded spans. The continuation search retains a 32-path base beam and a separate bounded personalized lane where existing token preferences apply. `ChineseBeam` streams incoming paths through the same heap selection as MSIME, and `ChinesePathOrdering` implements its libc++ introsort tie movement for terminal selection. A secondary text/arrival sort would change equal-score survivors. Base arithmetic stays in natural-log units through search and trigram rescoring; SI preference boundaries convert to bits. All decoders use `CandidateScoring`: one log-frequency coefficient, a 20-nat word insertion prior, and a two-nat Chinese-character cost instead of upstream's `ln(1e6)`. The old Chinese per-syllable score offset is removed. Per-syllable spelling observations and the same one-bit initial/synthetic continuation language costs enter both Chinese and lexical search. This intentional local scoring change reduces the bias toward low-frequency cross-boundary fragments that absorb a natural standalone character. A small character cost remains to discourage excessive splitting; it is not a corpus probability. Positive word-bigram increments participate during search, weighted by two, with outgoing rows reused per previous word within a column. Six distinct terminal sentences per lane are selected before word-trigram rescoring, including when only one sentence survives. Direct lexical choices include matching beginning-of-sequence context. All six retained alternatives per lane are emitted, deduplicated across base/personalized lanes. Automatic-confirmation requests use the same alternatives to suppress disputed boundaries without changing candidates or scores. Its word score and explicit candidate policy remain a heuristic objective, not a calibrated posterior.

Whole-input and eligible previous-word preferences participate before terminal presentation limits. Independent base terminal paths remain available. Prefix choices use a separately bounded pool before continuation selection, score against the consumed spelling, and preserve two distinct composed choices per consumed span. Strongest derivations retain single-lexical-unit evidence when identities coincide. Any path containing a personal phrase is excluded from token, whole-input and contextual learning. Explicit personal phrases continue using SI's existing store and retention/deletion rules rather than MSIME's archive.

Saved codes do not replace the default Chinese segmentation. The canonical lattice retains compatible saved nodes, while a separate personal-code cut can supply additional paths containing a personal node. That supplement cannot contribute ordinary Chinese alternatives or automatic-confirmation evidence. Direct saved prefixes use the existing sorted code index independently of the 12-node constructed fanout, and every saved node respects typed apostrophe boundaries. Constructed Chinese personal nodes use MSIME's 10,000 initial insertion prior, with the retained one-bit pin preference; this is a prior, not measured word frequency. No new retained personal data is introduced.

Exact Chinese words, alternative complete readings, sentences and completions compete by effective score. Fixed spelling aliases, bounded retroflex-initial splits and sparse lookup fallbacks retain source boundaries and score their actual typed reading. CandidateEngine deduplicates using language/text/source-span identity and globally sorts whole and prefix choices together by the shared effective score, without consumed-span or lexical-type precedence. Exact pinned personal phrases retain their explicit override; language categories have no front-position privilege. MSIME is the sole maintained Chinese dictionary source; the old Chinese data and maintenance adapter have been removed. English spellings and functionality are retained, while its data now comes from `Resources/English/si-english.sqlite`. The initial wordfreq estimates were converted once into the fixed Chinese-reference relative-frequency unit in `Data/DictionaryFormat.json`; Chinese stored weights are unchanged. Both source families use pinned weighted snapshots and SI-owned public overlays. English loads database rows once on a candidate worker and builds its existing immutable trie, with no generated English word/frequency Swift tables or per-key database load. Ordinary maintenance builds do not reimport upstream lists or recalculate existing weights. Shared costs make full scores comparable heuristic objectives; they are not calibrated probabilities. `LexicalCompositionDecoder` now reuses the bounded English continuation, terminal/prefix selection, canonical identity and learning machinery for mixed paths, querying the same ChineseLexicon directly instead of constructing another vocabulary/model per event. The former compiled Chinese reading tables and character-boundary model are not restored. Pure Chinese sentences continue through ChineseDecoder.

`LexicalCompositionDecoder` uses normalized source-letter positions for bilingual word edges. Complete Chinese syllables are enumerated under explicit apostrophe constraints, with at most seven syllables per word, 32 readings per end, 256 visited readings per start and 32 lexical rows per reading. Per-request lookup results are reused. English exact spans and final completions walk the existing trie and retain source casing. Chinese, English and mixed paths all use `CandidateScoring` word and language costs. Chinese adds its per-syllable spelling channel and English its word-prefix channel. The synthetic language-transition prior remains explicit. Positive Chinese word bigrams contribute within Chinese runs; English/personal boundaries reset that lexical context. The mixed lane accumulates the same Chinese word-trigram evidence within Chinese runs for terminal/prefix presentation. It does not add spelling aliases or initial-only Chinese edges.

The existing twelve-path state beams, separate base/personalized selections, two protected full spellings, bounded prefix pools, personal fanout and 4,096-byte output limit remain. Exact lexical English boundaries prevent token learning from promoting split-word alternatives. Paths containing personal/verbatim nodes never receive learning/context effects. Mixed results carry no automatic-confirmation trace. The engine queries every enabled lane, preserves language-aware identity, and ranks their whole and prefix results together by effective score. A mixed result stays available without a reserved leading seat. Direct English words and English/mixed sentence tokens use the same word/spelling cost. Explicit personal phrases use the shared 10,000-weight prior and code-spelling cost; unpinned phrases compete by score and no longer inherit a dictionary-size-dependent direct score. The engine retains all emitted results, with exact literal fallback.

`CandidateEngine` accounts for unconsumed input before comparing a prefix with a complete choice. `InputCandidate` keeps its base `rankingScore` separate from transient `remainingInputScore`; `LearningProfile` applies the existing consumed-spelling preference cap to the resulting `inputScore`. Shared immutable `CandidateSourceTrace` tails record word/source/UTF-8 boundaries, bounded token costs and exact Han syllable alignments. A matching full hypothesis supplies a compatible continuation without guessing text/source alignment. `CandidateWordContext` carries only the first/last two Chinese words, endpoint languages and corpus contribution needed to join bounded suffix estimates without duplicating BOS bonuses.

`CandidateContinuation` replays retained suffix paths and joins short bridges into them; it never generates a second visible sentence engine. A request-local cache deduplicates identical bridge queries. Missing continuation boundaries have a twelve-source-character bridge horizon, at most three splice targets, two joined tails per bridge and separate sixteen-state contextual/context-free lanes. Supplemental lookahead uses the existing decoders under reduced budgets; long unsupported gaps receive an explicit unknown-byte cost. Full generation, base/personalized beams and the 4,096-byte constructed-output bound remain. Prefix actions pay an explicit one-bit additional confirmation cost, with no display quota. Frequency data and saved base scores are unchanged. These request-local traces and hypothetical suffixes are not persisted or learned; personal/verbatim exclusions remain in effect. Interior Han alignments serve explicit prefix scoring only and do not authorize automatic confirmation.

`InputSession`, `LearningProfile` and `UserDictionary` remain UI-independent value types. One session owns its composition buffer, character-aware caret, recent chosen-word context and revision. Deferred edits retain exact literal spelling immediately. Only a result for the current revision, configuration and client can update candidates; final delivery rejects later provisional delivery. Candidate confirmation resolves full results before selecting. Return, cancellation, shortcuts and focus boundaries preserve or cancel exact spelling without waiting. Neither worker writes personal archives.

The shared spelling channel assigns sixteen times the geometric endpoint weight to a complete English word or Chinese syllable, then normalizes over its supported prefixes. Completing the last missing letter improves the spelling score by five bits. Chinese applies it per syllable independently of word segmentation; English direct lookup, cached preview and sentence edges use the same channel. This favors bilingual `ma` → `吗` without a language reservation or input-specific override. It also increases competition from fully spelled English word sequences against unfinished single words; see [ranking tradeoffs](UNIFIED_RANKING.md).

`CandidateSelection` continues to present at most 27 choices, preserving enabled-language identities and exact input. Ordinary whole/prefix and word/character candidates compete by score; the shortlist additionally applies the explicit Chinese sentence grouping/demotion policy described below. The engine retains full results. Prefix commits consume only validated exact source boundaries, keep the remainder marked/editable and avoid adding a space while a remainder exists. Candidate labels never become committed text.

Settings contains language, typing, direct-input, app-data, personal-phrase and update controls. It does not run candidate searches.

`PunctuationCandidates` supplies a fixed local table of English/Chinese alternatives for common ASCII punctuation. The shared engine includes these alongside direct provider and personal matches only when its explicit punctuationCandidatesEnabled option is enabled; this option defaults to false. Exact literal spelling is retained. A single trailing mark can be attached to complete, non-history word/sentence choices from the same engine; partial and incomplete choices are excluded. Repeated trailing punctuation does not recurse or expand combinations. Apostrophes after existing input retain their syllable-boundary meaning. `InputCandidate.punctuationLanguage` distinguishes punctuation variants independently of a preceding word's language and participates in cached identity. Explicit isPunctuation metadata also marks the literal fallback for badges and acceptance-spacing behavior, rather than inferring the enabled feature from its text. These variants inherit personal/verbatim exclusions, carry no automatic-confirmation evidence, never train vocabulary/context and never append an acceptance space. Constructed output remains bounded to 4,096 UTF-8 bytes. Full and provisional generation share this path; original input and stale-result validation remain unchanged.

With Show punctuation candidates and a language enabled, the controller starts marked composition for mapped punctuation even when the buffer is empty. The switch is off by default; when off, all punctuation outside composition passes through. Other symbols pass through outside composition. During composition the existing `PunctuationBehavior` policy still decides whether a key remains editable or confirms a candidate. Compact and expanded rows show small E/C badges immediately after punctuation text, with A for the As Typed literal fallback; tooltips and accessibility retain the full description. Badge letters use Core Text glyph-path bounds to center their visible ink horizontally and vertically, independently of NSTextField baseline padding. Only the selected text is committed.

## Automatic prefix confirmation

`LanguageSettings` persists a separate, initially disabled automatic-confirmation option. Its in-process configuration generation also changes when languages or punctuation/confirmation settings change, invalidating evidence even if a setting is toggled away and back between input events. Secure event input disables the option at the controller boundary independently of learning consent.

When enabled, full `CandidateRequest` generation captures transient `ConfirmationBoundary` evidence from the existing lattice: exact source-character counts (including ü/u: normalization and trailing separators) and cumulative output UTF-8 byte counts at up to eight leading, exact Chinese lexical nodes. Immutable shared trace tails bound per-path evidence without copying boundary arrays on each expansion. Capture stops at abbreviation, completion, personal, verbatim or English edges; full results retain earlier exact boundaries. Capture is disabled for provisional searches and ordinary engine callers. Evidence does not affect identity, scores, pruning, lexical presentation or output bytes.

On the background worker, `AutomaticConfirmation.prefixes` compares the leading whole Chinese candidate with every whole alternative within three model-score points, including eligible other-language competitors. This is a relative-score band, not a calibrated confidence probability. A proposed prefix must have identical committed bytes and source/output boundaries on every competitor; no textual-prefix or syllable-count guess substitutes for alignment. Mixed/personal/verbatim leaders, uppercase spellings, malformed output boundaries and non-Pinyin symbols do not produce proposals. An exact English word of at least four letters starting at a leading Chinese lexical boundary also suppresses proposals, independently of enabled languages; this protects tails such as `title` from being treated as Chinese-only spelling. Explicit syllable separators constrain this check. Literal fallback remains present but is not statistical evidence against every conversion.

`InputSession` retains at most eight client-local prefix observations. Only accepted full results advance stability, once per distinct appended spelling; pending, provisional, stale and cross-session results cannot confirm. Continuous confirmation requires two observations, six additional source characters since the first observation, at least four remaining output characters and eight remaining normalized letters. Pause confirmation requires at least 1.8 seconds since input, 0.6 seconds since the observation, a prefix of at least two output characters, two remaining output characters and four remaining normalized letters. Both use the same consensus proposals and complete lexical boundaries. Editing/navigation suspends evidence; only fresh end-of-buffer typing can restart it. Configuration, reset, commits and host boundaries invalidate evidence and the timer revision. A prefix commit resets observations, so a timer cannot repeatedly drain a stationary composition.

`SIInputController` attempts continuous confirmation on accepted result delivery. Its single cancellable, weakly captured main-actor pause task rechecks session revision, current client, settings and secure input before the same `automaticallyConfirm` method. Neither path synchronously resolves a search. `.automaticConfirmation` has zero learning weight and never creates previous-word context; no new persistence or surrounding-document reads are introduced. The ordinary prefix commit/marked-remainder path handles insertion exactly once without an English space. Already committed text uses ordinary host editing; there is no cross-host automatic reconversion/undo contract. Native focus/timer delivery remains an integration check.

## Personalization and storage

`ApplicationMemorySettings` is the sole automatic-learning settings model. The retired global `PersonalizationSettings`, its Settings views and `LearningStore` are removed from the app and package. Launch/termination load and flush only app memory and explicit phrases; input uses only the client app's profile. An absent, paused, disabled or secure profile yields base ranking. No disk I/O or dictionary initialization runs in the keystroke handler.

The UI-independent `LearningProfile` and `LearnedPreference` models remain shared ranking primitives for app vocabulary. Single-language frequency records can influence whole/prefix and eligible internal tokens before bounded limits, preserving base/personalized search beams and the shared 32-point cap. Chinese single-character outputs do not transfer into other compositions. Core contextual-ranking/session APIs remain available to library fixtures, but the application does not enable, store or expose previous-word pair learning. Old global archive schema versions are no longer loaded or migrated.

`PrivateArchiveFile` shares regular-file validation, bounded reads, owner-only permissions, atomic replacement and erase mechanics across the remaining storage actors. App memory provides an actor-isolated existence/deletion operation for the retired `preferences-v1.json` path without decoding its contents. Settings exposes explicit deletion with independent progress/error feedback. Old consent flags are ignored and removed only with that deletion. Existing files are not erased or assigned to guessed app scopes; the inactive old archive receives no automatic retention maintenance.

`UserDictionarySettings` owns the separate explicit phrase dictionary and uses `UserDictionaryStore` for local persistence and file import/export preparation. JSON imports validate all phrases, merge into a copy, preserve existing content/pin settings, and apply only if no intervening edit/clear changed the revision. Capacity errors leave the entire import unapplied. Storage and import/export errors remain distinct so a later successful save cannot hide a failed import. Phrases retain until explicit deletion, independent of learning. Cached code/identity indexes support direct full/prefix matches and intermediate lattice nodes; any derived path containing a personal node is excluded from automatic learning and prior-word context.

### App vocabulary and history

`ApplicationMemory` is a UI-independent value model with separate `ApplicationVocabularyEntry` and `ApplicationHistoryEntry` collections. Bundle identifiers come from the installed SDK's `IMKTextInput.bundleIdentifier()` contract, not the foreground process or document contents. A vocabulary entry retains its normalized consumed spelling/candidate identity, noncontextual `LearnedPreference`, aggregate confirmation count, base score and lexical-unit evidence. Explicit and default confirmations increment its count; the existing 14-day decay and 32-point ranking cap apply. History, personal/verbatim and automatic/delimiter commits never train it. Records are capped at 5,000 across apps with 90-day inactivity expiry. No automatic decomposition into newly saved words occurs.

`ApplicationMemorySettings` owns independent vocabulary/history consent and per-app exclusions, all disabled initially. The controller uses only the client app's profile; disabling vocabulary, excluding an app, or enabling secure input yields base ranking. The inactive legacy archive is retained until explicitly deleted. Explicit personal phrases remain separately available. Immutable per-app snapshots are cached between changes, use revision identity for configuration comparisons, and travel in `CandidateRequest`. App words supplement the same `CandidateEngine` merge; the profile also reaches existing decoder token/whole preference paths.

Each `SIInputController` owns an `InputHistoryDraft`, client identity, configuration generations and optional expected UTF-16 host insertion offset. Successful SI insertion and printable passthrough events append source/output fragments; replacement punctuation is appended only once. Drafts are bounded to 4,096 bytes per source/output and expire after five minutes without activity. Return consumed by composition retains its existing literal-commit behavior. Only unmodified Return/keypad Enter passed through to the host closes and deduplicates a unit. Escape, committed-text editing/navigation, shortcuts (including paste), focus/commit callbacks, consent/configuration/secure changes, personal/verbatim paths and automatic confirmation discard the draft. An invalid draft cannot resume from a suffix before the next delimiter or new client. Supplied selection offsets detect unexpected caret movement without reading any text. Hosts that omit offsets/events or transform text remain an integration limitation; a delimiter proves neither sending nor command execution.

History entries retain exact spelling/output, required language identities, app identifier, aggregate use count and last-use time; no sequence of individual uses is retained. They are capped at 1,000 across apps and expire after 30 days. Matching runs on the candidate worker, requires exact already-committed source/output byte prefixes, normalizes the remaining spelling for prefix lookup, and returns at most three unique completions. History candidates carry a distinct identity and source spelling, cannot train vocabulary/previous-word context, and never append an English space. The engine inserts them after its first two whole choices; the window preserves the first history choice alongside its existing protected language/literal choices. Empty compositions remain empty. Output suffixes are computed from UTF-8 boundaries to preserve exact committed bytes. Recording a reused completion keeps its original source spelling, so subsequent uses reinforce the same history entry.

`ApplicationMemoryStore` confines all file I/O to an actor using `PrivateArchiveFile`, schema 1, a 64 MiB read/write limit, owner-only permissions, atomic replacement and revision-ordered saves/deletion. The archive is `SI/Personalization/application-memory-v1.json` in Application Support. Writes coalesce for 300 ms and flush at normal termination; startup and daily maintenance prune expired rows. Corrupt/unsupported data pauses recording/suggestions until explicit clear; failures are visible. Settings provide per-app pause, search, entry deletion, per-type/per-app clear and full archive erase. Consent/deletion changes invalidate queued results, and mouse confirmations revalidate current candidates before committing.


The package compiles the same storage actor and observable settings models as the app under separate test targets. Conditional imports bridge package modules without duplicating implementations. SwiftUI views remain in the app target.

## macOS integration

`LanguageSettings` persists an initially empty set of direct-input application bundle identifiers and advances its existing configuration generation when a rule changes. `ApplicationDiscovery` scans standard Applications folders and explicit/running app URLs on an actor only while the Settings manager loads or refreshes. It reads bundle metadata, skips nested app helpers, and deduplicates by identifier. Discovered bundle URLs stay in memory for row-local `NSWorkspace` icon loading when a row appears; paths and icons are not persisted. Missing apps use a generic application icon. The manager retains missing enabled identifiers for removal and supports manually selecting apps elsewhere. Discovery and icon loading never run in key handling or read input/document text.

`SIInputController.configureSession` checks the actual IMK client's identifier before configuring conversion and returns false for direct input. Key handlers then return false before interpreting letters, candidate numbers, punctuation, Return or navigation. Mouse selection, page/expansion actions, candidate delivery, composition callbacks and automatic-confirmation timers recheck the same boundary. Entering direct input resets the session, invalidates both pipelines and pending history, clears selection/presentation, and inserts any exact pending spelling once through the existing insertion path without learning/history or a suffix. An already-running search cannot restore the reset session. Rules do not change enabled languages or the registered input source. They cover an entire app rather than particular browser tabs, DOM fields or editor panes. They suppress new vocabulary/history recording and use, without deleting existing data or modifying consent.

`SIApplication` starts an AppKit application. `AppDelegate` retains one `IMKServer` for the process lifetime. `mac/Support/Info.plist` names the connection and the stable Objective-C controller class `SIInputController`; it declares a background input method with one input source and no mode dictionary. The bundle and source identifier is `com.caterm.inputmethod.si`, including the `.inputmethod.` segment used for InputMethodKit discovery. `TISIntendedLanguage` is `en` so SI is discovered under English; its character repertoire still includes Latin and Simplified Chinese scripts. This system classification does not choose an active language inside SI. Showing Settings changes the process activation policy to accessory so the background declaration does not prevent displaying the settings window.

The local installer builds Release by default (`./scripts/install.sh Debug` explicitly opts into an unoptimized debugging build). It calls `TISRegisterInputSource` after installing the signed bundle, then queries only SI's bundle ID (including disabled sources) and requires exactly one selectable keyboard input method. It never enables/selects an input source. `--check` performs only the verification query. Existing `com.caterm.si` installations are backed up and replaceable by the installer. `SettingsDefaults` deliberately retains the original `com.caterm.si` domain for language, punctuation, and learning consent; archives remain at their existing Application Support paths. No consent is reset or inferred by the bundle-ID correction.

`scripts/reinstall.sh` explicitly opts into stopping the current user's exact-name `SI` processes with SIGTERM, waiting up to five seconds before SIGKILL and another bounded wait. It then delegates to the unchanged installer, retaining both running-process checks and the existing backup/rollback path. A restarted process can still cause installation to abort. It does not select/enable input sources or force logout; pending composition and unsaved learning may be lost when stopping SI.

`SIInputController` adapts key events to the core and maintains marked text in the client. It owns one `CandidateSelection` and one nonactivating AppKit `CandidatePanel` per client. Number labels, highlighted rows, arrow/page navigation, Space confirmation, and mouse clicks use the same selection/page state. A composition starts collapsed, with six choices per horizontal page; expanding shows nine choices per vertical page. Switching layout preserves the selected candidate and recomputes its visible page/number; ending the composition resets expansion. Row labels remain presentation data; only validated candidate text is committed. Objective-C callbacks lack Swift actor annotations. The UI callback boundary uses `MainActor.assumeIsolated` explicitly; this relies on InputMethodKit delivering those callbacks on the main thread. Non-Sendable Objective-C callback arguments are captured using narrowly scoped `nonisolated(unsafe)` locals, and the controller explicitly declares `@unchecked Sendable` while its mutable state stays main-actor isolated. This boundary must be exercised during manual integration checks.

`MarkedTextState` suppresses repeated host updates when the exact composition bytes and UTF-16 selection have not changed. Provisional/final candidate deliveries update the panel without restarting identical host marked text. Edits, caret movement and cancellation still send the required update; commit, deactivation and client changes clear the cache. Async delivery also checks the active client before updating the session. Identical visible candidate identities retain their row views; unchanged row configurations avoid label/accessibility writes. Changed identities still replace rows so removed controls cannot confirm replacement text. Panel resizing finishes layout before display. These remove redundant refresh paths; automated state/view checks do not prove that a reported transient system window is eliminated.

Candidate panels additionally share one weak main-actor visibility owner. Activation or a current key event claims that owner and hides the previous panel; result delivery, timers, mouse callbacks and panel rendering cannot reclaim it. A late old-client deactivation cannot release a new client's owner. This shares only presentation ownership, never composition buffers or selection. The `activateServer:` override uses the existing main-thread IMK callback assumption, checked against the SDK declaration; actual callback ordering remains a native integration check. Per-controller presentation revisions also reject work superseded by synchronous reentry during host marked-text, insertion and geometry calls. Geometry resolves on a local value copy to avoid overlapping mutation of controller anchor state during such reentry.

`InputCandidate.lexicalTokenCount` carries transient lexical evidence independently of identity, score and commit text. A single exact lexical/personal prefix is distinguished from a constructed fragment; abbreviation-only matches do not carry single-word evidence. Deduplication retains this evidence without using it to reserve display positions. `CandidateEngine` merges whole candidates and prefixes by effective score, using only consumed source spelling for prefix learning/context. Neither complete status nor longer consumed spelling overrides score; canonical identity resolves equal scores and explicit personal pins retain their existing override. `CandidateShortlist` supplies the shared ordered 27-choice policy used by the window and offline quality tool; `CandidateSelection` applies it and pages the resulting presentation order. Generated Chinese sentences carry explicit transient provenance, independent of lexical-unit count, identity and score. Following MSIME's host policy, the shortlist groups three same-length readings of at least three characters beside the first reading, or one for two-character readings, and moves the rest behind ordinary choices. All bounded ordinary Chinese sentence alternatives remain in the shortlist; direct lexical duplicates keep lexical placement. First words and characters have no special placement. The 27-item shortlist retains complete choices per matching language/mixed identity, the first history suggestion and exact literal spelling while preserving ordinary relative order outside sentence grouping/demotion. History keeps its insertion after the first two whole choices, reapplied after sentence placement. The exact literal stays last. Compact/expanded pages, numbers and mouse actions use the same client-local shortlist. The engine retains all emitted results.

The controller consumes navigation and number-selection events while composing. `CandidateSelection.action` maps event key codes/characters to moves or numbered choices; both the view and commit lookup read the resulting page. There is no `IMKCandidates` instance or dependency on its selection-key display, identifiers, or callbacks. Out-of-range row numbers do not commit another candidate. Shortcuts retain literal passthrough, and outside composition these keys pass through. Candidate edits/reset invalidate the previous selection. Mouse buttons return candidate identities and use the same current-candidate validation/learning path as digit keys.

The panel never becomes key/main, preserving the host's input focus. `CandidateAnchor` first requests IMK's inline-session-relative UTF-16 `attributes(forCharacterIndex:lineHeightRectangle:)` at the composition start, then at the composition caret if necessary. The SDK specifically provides this method for candidate-window placement. Fresh non-origin inline geometry replaces any earlier document fallback, so a cached fallback cannot pin the panel away from the input. Temporary inline failures retain that composition's established inline anchor. A document-relative `firstRect(forCharacterRange:actualRange:)` is a fallback only: its returned actual range must contain the requested zero-length insertion position. Missing/unrelated/overflowing ranges are rejected. A global-origin rectangle needs corroboration from both geometry channels instead of flashing a panel at an ambiguous default origin. These queries read geometry only, without surrounding text. Cached rectangles belong to one client/composition and must remain on a connected screen. Commits, cancellation, activation, client changes and deactivation clear them. With no valid query or cache, the panel hides rather than inventing a position. `CandidatePlacement` uses AppKit screen points directly, without a Retina multiplier or coordinate flip, places below the anchor or above when necessary, and clamps to the containing screen's visible frame. Page buttons update the same model; wheel and trackpad scrolling are ignored in both layouts. Buttons expose candidate text/language/number and selected state through accessibility; clipping long labels does not alter committed text, which remains available in tooltips. The package's `SIPresentation` target compiles the same selection and AppKit view sources for focused regression checks; this is not a second engine.

`CandidateStyle` supplies dynamic warm-neutral light and dark palettes. The selected candidate uses a soft peach/umber background with an orange number and ordinary adaptive label text. The system Increased Contrast preference strengthens the card border and outlines the selection. The default 36-point-high strip lays out up to six 28-point candidate buttons horizontally and reserves a trailing expansion chevron with a subtle divider. Each button keeps a compact gap between its number and candidate labels and fits its text and source symbol, capped at 280 points. Extra retained window width does not stretch compact buttons; narrower screens proportionally shrink them without overlapping the chevron. Text-cell insets are included in width measurement; labels with too little room to draw a complete glyph hide rather than clipping through a symbol. Full text remains in accessibility and tooltips. Expanded mode uses a vertical card within 180–600 points, with a collapse chevron and a footer whose page count/previous/next controls appear only for multiple pages. Ordinary word language descriptions are hidden visually; punctuation variants show small E/C badges immediately after the text in both layouts, and their literal fallback shows A (As Typed). Compact prefix/personal/literal/verbatim hints use small symbols. Expanded rows omit `First N` consumption labels; other source hints remain. Exact consumed spelling stays in tooltips and accessibility descriptions. Language identity, full text, exact consumed-input descriptions and selection state remain available in accessibility labels and tooltips. Both layouts retain pending geometry, refresh rows on accepted provisional delivery, and disable selection, paging and expansion until full results arrive. Horizontal and vertical scrolling never change pages or selection. Clipping labels never changes committed text.

`scripts/generate-icons.swift` produces `InputSourceIconTemplate.tiff` on a 16-point canvas with 16×16 and 32×32 pixel representations. The rounded badge is opaque, while the SI glyphs are cut out with destination-out blending. `TISIconIsTemplate` is true, allowing macOS to tint this alpha mask for menu-bar appearance and selection without flattening opaque lettering and background into a solid block. There is no separate alternate color bitmap. The new resource name distinguishes it from the former full-color assets; installed sources retain their identifiers, connection, and language settings. Core Text glyph bounds, rather than the font's full line box, determine centering. Both representations carry the same logical size, avoiding a 32-point icon in system input-source rows. Resource previews and bundle checks do not establish actual menu-bar rendering; verify the installed update in the login session.

App Sandbox is disabled because the legacy InputMethodKit server uses interprocess connections with text clients. SI does not request Accessibility or Input Monitoring permissions and does not install a global event tap. `LSUIElement` keeps the input-method process out of the Dock. Closing Settings does not terminate the server.

`LanguageSettings` is main-actor-isolated and observable. It persists enabled-language booleans and the punctuation behavior in the stable `com.caterm.si` defaults domain. Both languages default to enabled. A separate punctuation-candidate boolean defaults to false, persists independently of the delimiter policy and increments the configuration generation when changed. InputSession copies this option into each immutable request engine; reconfiguration rejects obsolete results while retaining exact marked input. Absent or unknown punctuation preferences default to Keep Composing (`asTyped`); explicit saved smart/confirm policies remain selected. Settings take effect when the next key event refreshes a composition. Disabling all languages leaves literal input available. Shift and Caps Lock do not select a language mode.

The Xcode Run scheme passes `--settings`; normal system launches keep the process in the background. The installed app exposes Settings through the input menu and on reopening the app.

## Software updates

`AppDelegate` retains one observable, main-actor `AppUpdater` for the process lifetime and passes it to Settings. IMK dispatches the input-menu selector to `SIInputController`, which forwards it to that same instance. Both menu availability and the forwarding callback use the existing main-thread callback assumption; no client/composition state is shared with the updater and no additional unsafe isolation escape is used. This follows the installed SDK's `doCommandBySelector:commandDictionary:` contract rather than relying on an NSMenuItem target surviving the system menu bridge. Sparkle's KVO availability is delivered through a main-actor task, and the action rechecks the live updater before starting a check. Closing Settings does not tear down either the updater or `IMKServer`.

The app target alone links pinned Sparkle 2.10.0. Core/storage/package tests have no network or updater dependency. Only Release builds at `~/Library/Input Methods/SI.app` start Sparkle; Debug and uninstalled copies explain the disabled action in Settings. `SUEnableAutomaticChecks`, `SUAllowsAutomaticUpdates`, `SUAutomaticallyUpdate`, and `SUSendProfileInfo` are false. A user-initiated check uses the standard Sparkle UI, validates the EdDSA archive signature before extraction, and requires the user's install choice. Normal termination still flushes learning and phrases before replying. The app-bundle update replaces SI in its existing location and restarts it; native input-source recovery and host/focus behavior still require manual verification.

`SI_UPDATE_ARCH` defaults to `universal`; packaging explicitly sets it to the selected architecture and sets `SI_UPDATE_FEED_URL`. The resulting `SUFeedURL` points to SI's separate `si/channels/mac/stable-<arch>.xml`, so a Universal installation stays on the Universal channel on either CPU. No input text, phrase content, learning data or host-document content is supplied to Sparkle. Its update preferences remain separate from the existing language/learning domain. See [privacy](PRIVACY.md#software-update-requests).

## Distribution tooling

`scripts/package-dmg.sh` and `scripts/release.sh` share `scripts/release.py` and the existing SI Xcode target. Packaging builds Release for Universal or a selected architecture, signs a staged copy including Sparkle's nested helpers, and wraps it in a native Installer package inside the DMG. `scripts/installer/Distribution.xml` restricts installation to the current user's home domain and requests `RequireLogout`; macOS Installer owns the final Log Out button and normal save/cancel handling. Its preinstall script rejects a running SI or foreign bundle and copies existing SI to the established backup directory. Bundle relocation is disabled so other built/installed copies cannot redirect the payload. Native strict-ID matching is disabled only to permit the legacy `com.caterm.si` migration; preinstall explicitly permits only that ID and the current SI ID. Publication also notarizes/staples the app and produces an app-only update ZIP signed with Caterm's existing Sparkle Keychain identity; it never routes the home-only pkg through Sparkle's privileged package installer. Publication requires Application/Installer signing, notarization and a clean checkout, includes corresponding committed source, and verifies anonymous R2 downloads before conditionally promoting the independent SI JSON channel and then the Sparkle XML feed. The XML uses `CURRENT_PROJECT_VERSION` for comparison and `MARKETING_VERSION` for display. Cached archives have their EdDSA signature rechecked. Downgrades, same-version conflicts and competing conditional writes are rejected. All build/release files stay under `.build/` by default. Running packaging does not install, launch or log out; installation/logout requires the user to run the package and click through macOS Installer. See [RELEASING.md](RELEASING.md).

New publications increment the Xcode patch/build metadata after preflight and commit only that version file, keeping the built app and corresponding source archive tied to the same revision. An architecture-local pending marker under `.build/` preserves the chosen version for failure retries. Successful publication clears the marker; `--no-bump` explicitly reuses the current version for another architecture or a retry without local state. Dry-run/local packaging do not mutate versions or Git history.

## Offline model experiments

`llm/` is a separate Python/PyTorch spelling-to-text framework with a randomly initialized 403,069,952-parameter encoder–decoder. It has no dependency from the Swift package/app and does not replace the production candidate engine. `llm/csv_data/` imports static `input,target` CSVs from explicit train/validation/test directories; filenames label source groups and an optional language defaults to Chinese. It checks source declarations, rejects cross-split normalized input/target overlap, deduplicates within a split and freezes source bytes/hashes with model-ready JSONL. There is no seed-based content generation, Pinyin conversion, noise augmentation, source-manifest importer or automatic split path.

The tokenizer fits training rows only and preserves unknown Unicode through UTF-8 byte fallback. Training reads train/validation only; explicit held-out candidate evaluation can additionally use a frozen external CSV benchmark's selected split. Checkpoints retain optimizer/RNG/batch position, and inference export omits training state. Prepared artifacts are ignored by Git; maintained CSVs are source files. Setup, prepare, train/resume, validation/test, inference/export and smoke scripts use the same isolated environment. Each ordinary stage script has defaults from `llm/scripts/defaults.sh` and invokes only its own task; `data.sh` aliases preparation and `run.sh` aliases training. They share explicit versioned data/run/report paths. Setup and separate candidate evaluation/export require their own invocations; training retains its periodic validation loss and checkpoints.

Old datasets, generator code, configs and smoke artifacts were removed. Previously trained weights/run records remain usable for inference/export, but their deleted prepared data and compatible runtime are not available for resume. New CSV training uses a new experiment with strict dataset/config/code identity checks.

The model's MPS path materializes full encoder/cross-attention masks to avoid a reproduced PyTorch 2.6 shape assertion, preserving padding and causal constraints. Numerical CPU/MPS comparisons and varied-length validation cover that repair. CPU/CUDA retain their existing mask path, and resume releases the loaded CPU checkpoint payload after state transfer. These checks do not establish representative conversion quality or host compatibility. Native candidate identity, enabled-language coexistence, spelling alignment, prefix commits and cancellation remain SI's core/controller contracts. See [the training guide](../llm/README.md).

## Extending language support

1. Add a stable language identifier and English display name to `InputLanguage`.
2. Implement a `CandidateProvider` with local, deterministic behavior and licensed data.
3. Register the provider in `CandidateEngine` and expose its enabled preference in Settings.
4. Test ambiguous sequences, disabled-language filtering, deterministic ranking, literal fallback, and composition resets.
5. Document dictionary provenance, performance characteristics, and limitations.

The new Chinese implementation and its current limits are described in the core section above and in [the pinned MSIME algorithm study](MSIME_ALGORITHM.md). English-only and Chinese/English lexical composition share the bounded search, with complete Chinese-word edges fetched from the maintained dictionary. Both lanes share the same public engine/session and existing personal-data controls.

The previous mixed decoder's guarded ASCII/CJK byte comparison and canonical Unicode fallback remain in `LexicalCompositionDecoder`. The measured performance figures recorded before this migration describe that previous implementation; they do not establish performance of the Swift MSIME adaptation. Exact output bytes are never normalized for committing.
