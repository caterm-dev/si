# Architecture

## Product contract

SI exposes one macOS input source. Settings contain a set of enabled languages, not an active language. Every enabled provider is queried for the current composition. Matching candidates coexist; ambiguity is a choice for the user rather than a reason to switch modes. Literal input is always offered.

## Data flow

```text
Host application key event
  → SIInputController
  → InputSession (buffer and enabled languages)
  → immutable CandidateRequest → client-local coalescing queue → background actor
  → CandidateEngine
  → enabled English lookup + shared Pinyin/mixed/personal-phrase lattice
  → deterministic merged candidates + optional learning bonus + literal fallback
  → revision-checked CandidateResult → InputSession
  → client-local selection/page state → nonactivating AppKit candidate window
  → committed text in the host application
```

`CandidateEngine`, `InputSession`, `LearningProfile`, and `UserDictionary` are value types with no UI or persistence dependencies. The default engine combines English lookup and one shared lattice search. Injectable providers declare required languages for isolated tests/extensions. The merge rejects disabled-language, empty, malformed mixed, and invalid-prefix results. Deduplication keeps the strongest effective score for each language/text/consumed-prefix identity, including learning; ties prefer an explicit personal phrase. Whole candidates precede prefixes; prefixes covering more input precede shorter ones. Within each group, sorting uses fractional effective score and a cached stable identity, followed by the original-text candidate. There is no global candidate cap. Mixed paths explicitly carry a combined-language identity and require both languages. A personal phrase's language is saved explicitly, not inferred from its script.

Chinese built-in entries retain exact upstream integer weights, with no per-entry authored scores. At decoder initialization, one global scale derives `100 + log2(max(1, weight) / maximum_upstream_weight)` as a Double; zero/unweighted coverage uses the one-count floor without changing stored provenance. Positive score differences encode exact upstream weight ratios logarithmically rather than rounding them into decimal buckets. These cached lexical scores drive exact/completion edges and provisional pools; direct candidates preserve fractional ranking separately from their compatibility integer score. English exact matches retain 110 and English completions 75/85; Chinese completions subtract 16 and abbreviations retain their spelling penalty. Personal phrases use 115 for full codes, 180 when preferred, and 80 for prefixes. Constructed paths retain segmentation costs and a four-point cost for each language transition. Learning adds up to 32 frequency/recency points and 12 optional previous-word points with a 14-day half-life. Global search/presentation policies and explicit personal preferences remain separate from upstream lexical evidence. There is still no trained sentence-context model; source priors alone can rank an unnatural sentence first.

Provisional Chinese lookup caches the 16 highest-scored entries for each full reading during decoder initialization, with source order breaking score ties. Abbreviation variants share that cache. Exact and completion hints use this scored pool instead of taking the first 16 source rows: source order alone must not discard a common `shuo` candidate and promote a `shu` + `o` split. The existing preview reading/edge budgets still apply, so hints remain approximate. Final lookup continues to use every entry for the matching reading, with the existing bounded path search; this adds no sentence model or typo correction.

The shared lattice also returns all-English paths containing multiple lexical words. These paths carry a spaced English rendering alongside the original concatenated rendering, so `iwanttobuild` can yield `I want to build` without changing mixed outputs such as `helloworld中文`. Path comparison, identity and final scoring use the spaced rendering while the path remains entirely lexical English; adding a Chinese, personal or verbatim node drops that rendering. Direct single-word English results still come from the English provider. Word casing follows the existing lexical casing rules, completion flags remain explicit, and prefix boundaries still refer to the exact source spelling including apostrophes. The existing per-state beams and 4,096-byte output limit apply. This is lexical segmentation, not grammatical sentence ranking or missing-letter correction; ambiguity can yield several spaced alternatives. Learning retains only the selected whole/prefix aggregate and does not automatically save component words.

Eligible single-language frequency records adjust matching lattice edges before pruning. Chinese records with single-character output remain available for whole-input/prefix ranking but are excluded from the token index and token bonuses, including when another multi-character record shares their spelling. Chinese words with at least two characters and English records remain eligible. Each path accumulates token bonuses weighted by consumed normalized-letter lengths, then divides by its consumed length. Continuation search retains a 12-path base-cost beam plus up to 12 personalized paths per state where token preferences apply. Direct lexical/personal matches remain independently available. Final frequency adjustment is the maximum of the path's average and its whole-input preference, capped at 32, plus at most 12 for a previous-word pair. Direct single-edge candidates use ordinary whole-input learning.

When matching token bonuses are positive, the decoder derives exact lexical English endpoints from the existing edges. A path carries the furthest such endpoint reached from starts in its contiguous English run. Continuing with another token before that endpoint marks a split English word and suppresses token bonuses for that entire constructed path, including later continuations. This prevents isolated word preferences from promoting `tit` + `le` over intact `title`, whether the second token is Chinese `了` or an English completion such as `learn`; no base costs or direct results change. Whole-input and previous-word preferences still apply to deliberate alternative segmentations, including prefix choices scored against their consumed spelling. Explicit separators constrain the exact edges, and a continuation after the English endpoint remains eligible for token learning. Personal/verbatim paths retain their existing learning exclusions.

Continuation identity includes the pending English endpoint and split flag because they affect future learning eligibility. These alternatives share the existing 12-path per-state budgets rather than adding states or enlarging the beams. Terminal identity omits future-only boundary metadata and retains the strongest effective derivation of each output. The endpoint tracking is inactive without positive matching token bonuses, including paused, deleted, expired, secure, and unrelated preferences. This is a conservative lexical safeguard; ambiguous words and sentence quality still need broader evaluation.

Completed paths use their actual candidate scores before terminal pruning, including whole-input and eligible previous-word preferences. The terminal retains up to 12 base-ranked and 12 personalized paths per state, with separate states for complete and final-completion paths; a low-cost direct entry cannot displace a higher-scoring equivalent composed result. Large terminal batches use bounded ordered selection after scoring. Prefix presentation independently retains two best distinct outputs per language combination and consumed span, scored against that span's exact source spelling before continuation pruning. Whole candidates still precede prefixes, and longer prefixes precede shorter ones. Intermediate search costs remain optimized for extending paths. These bounded presentation pools cannot recover a path whose earlier prefix was already lost. Deduplication uses the same effective score at decoder/engine merge, without adding learning twice. Previous-word pairs affect terminal/prefix presentation and merge, not internal token transition costs; internal pair/sentence scoring remains future work.

`InputSession` owns one composition, refreshes candidates after edits or configuration changes, and rejects stale candidate commits. Synchronous generation remains the default for previews and ordinary core callers; the input-method controller selects deferred generation using that same engine. Deferred edits retain exact literal spelling and produce an immutable `CandidateRequest` with an opaque revision ID. Each sealed stage result can apply once, only to its still-pending request. An accepted provisional result updates candidates but keeps the full request pending; full delivery clears it and rejects later provisional delivery. Provisional selections resolve full candidates and remap only a validated provisional identity before committing; literal commits do not wait. Edits, configuration changes, commits, reset, and replacement compositions invalidate earlier requests; matching text in another client does not make a result valid. A separate controller exists for each InputMethodKit client session. `commitResult` captures consumed source input, the validated candidate, commit reason, and remaining input. A whole commit clears composition; a prefix commit refreshes the editable remainder. Source mapping preserves boundaries through apostrophes and ü/u: normalization. Invalid selections become literal commits and cannot produce learning feedback. Space appends an English space only when no remainder is pending and the accepted candidate ends in English (or is literal).

The controller uses two `CandidatePipeline` instances per client: one full search and one provisional search, each with at most one in-flight snapshot and one latest replacement. Independent shared worker actors prevent a slow full search from serializing early hints behind it. Both actors work with immutable snapshots; client/UI state remains on the main actor. A new edit replaces pending work in each lane. Cancellation/focus/commit invalidates both, and delivery rechecks languages, dictionary, learning consent, secure-input suppression and context before acceptance. Neither lane accepts obsolete revisions, matching text from another client, duplicate stages or a preview after full delivery.

Provisional generation reuses `PinyinDecoder.compositionCandidates` with bounded edge lookup, the same lattice, source mapping, output-byte limit, learning safeguards and engine merge. It scans at most eight full-reading groups and a precomputed sixteen-entry base-score pool per group for a span, limits terminal completion lookups to eight groups/English entries, and keeps two outputs for each of up to two spans per language/completion class. Span selection uses continuation cost per consumed letter and matching token preferences. Chinese initials/mixed abbreviations and exhaustive lexical/personal completions remain in the full search; direct personal nodes remain eligible in provisional paths and retain learning exclusions. Direct English hints use at most eight shared Trie matches. Custom injected providers have no bounded-hint contract and run only in the final stage. These provisional limits do not alter final search beams, direct alternatives, merged output or Settings preview results.

Marked spelling updates immediately. Until an early result arrives, the panel retains its last rows; accepted current provisional hints then replace them while full generation remains pending. Pending layout retains at least its previous size, may grow to fit new hints, and does not hide/order-front the window per key. Pending rows/page/expansion actions remain disabled. Full results restore normal interaction and content sizing. A hidden panel starts with the new composition's literal or current hints. Space, digits, candidate navigation and optional punctuation confirmation synchronously resolve a pending full request before confirmation; these boundaries can still block on one full search. Literal Return/shortcuts, cancellation and focus commits invalidate work without waiting. Removed row actions remain rejected. This adds a limited mode of the shared decoder, not another engine, and does not promise native key-to-screen latency.

Continuation pruning uses bounded ordered selection per existing state, with separate base/personalized beams, instead of sorting the full incoming pool. Canonical identities, boundary metadata, the 12-path budgets, and original stable tie order remain intact. Prefix presentation still occurs before continuation pruning, and all direct lexical/personal results remain independent of those bounds.

The composition caret is stored as a whole-character offset. Insertion and forward/backward deletion operate at that caret; inserted Unicode scalars may join adjacent graphemes, so insertion recomputes a valid whole-character boundary. Marked-text selection converts the caret to a UTF-16 offset. Left/Right and Home/End edit composition; the controller explicitly handles Up/Down and Page Up/Down through its client-local `CandidateSelection` state.

`CompositionBoundary` resolves punctuation/Tab according to `PunctuationBehavior`. The default `asTyped` policy now means Keep Composing: punctuation/symbol keys are inserted at the composition caret and remain marked/editable. `keepsInComposition` identifies symbols that do not require a candidate search, including ASCII period under every policy and non-confirming code symbols. The controller appends them through the same `InputSession` edit/revision path and returns true, preventing duplicate host insertion; normal asynchronous generation invalidates obsolete results. Symbols outside composition pass through. Rejected punctuation confirmations carry `continuesComposition` and are appended too, rather than committing the original text. Existing smart/confirm policies remain optional and preserve their English/personal/prefix safeguards and replacement rules. Tab remains a host boundary (literal in Keep Composing); Return, shortcuts and focus changes commit exact spelling, Escape cancels, and Space/digits/mouse retain candidate confirmation. Digits remain selection shortcuts. Apostrophes retain their existing Pinyin-boundary behavior. Symbol-bearing input always keeps its exact literal candidate; ordinary lexical decoding may yield no other result. Symbol insertion does not create learning feedback. Optional delimiter commits still do not train learning or keep previous-word context. Native event delivery remains unverified for this change.

## Personalization and storage

`PersonalizationSettings` is main-actor-isolated and observable. It loads the local profile at launch, exposes an immutable value snapshot for synchronous candidate ranking, and asynchronously saves aggregate feedback through the `LearningStore` actor. No disk I/O or dictionary initialization runs in the keystroke handler. Unchanged session configuration avoids recomputing candidates before each edit.

Learning is off by default. Explicit selections contribute weight 1; default acceptance contributes zero and neither creates/updates records nor becomes previous-word context; original-text commits, cancellation, host-boundary commits, and candidates containing personal/verbatim spans contribute nothing. Prefix feedback uses only the confirmed source prefix. Secure event input disables both recording and personalized ranking. Stored keys preserve explicit syllable boundaries, normalize case and ü/v spelling, and include language identity and output text. Only aggregate strength and the most recent use time are retained, with a 5,000-entry cap and 90-day inactivity expiry.

Token ranking reuses those records without extra persistence or automatic sentence decomposition. In-memory spelling indexes cover token frequency and all retained preference types, including mixed/contextual records. Both rebuild on load/prune and update through record/delete/clear. The token index excludes single-character Chinese outputs, including in existing archives; whole-input ranking retains them. The archive schema is unchanged. Old records do not identify their original commit reason and cannot be selectively erased as default-acceptance records. Query-local immutable ranking snapshots normalize each full/prefix spelling once and skip whole-record lookups when its spelling is absent. Spellings are also normalized once per shared edge span; no per-query profile scan or disk access is required. Token bonuses are ephemeral candidate metadata and remain zero for any path containing a personal/verbatim node. Empty ranking profiles, including pause and secure input, produce base ranking.

The separate context option is also off by default. `InputSession` holds only one prior nonliteral, nonpersonal candidate with its confirmation time, eligible for five minutes. Cancellation, literal/host boundaries, language changes, focus/deactivation callbacks and navigation outside composition clear it. A consent/clear generation token invalidates existing controller contexts even when a user turns learning off and back on between key events. The current commit captures eligible prior context; the learning profile optionally records a second aggregate pair entry. Pair records share capacity/expiry with ordinary preferences. No surrounding document text is queried. Native focus delivery remains an integration check.

`LearningStore` bounds input file size, validates archive version, sanitizes records through `LearningProfile`, and atomically replaces a JSON file in an owner-only directory. Revision guards prevent older queued saves from undoing newer deletion requests. Saves are coalesced for 300 ms; orderly application termination flushes pending changes. Load failures pause learning until explicit clearing; write and clear errors are surfaced in Settings. Expired records are physically removed on load and through daily maintenance while SI runs. See `docs/PRIVACY.md` for data fields, controls, and limitations.

Learning schema 2 adds explicit mixed identity and optional prior-candidate context; schema 1 migrates on load. The stable private filename is unchanged. `PrivateArchiveFile` shares regular-file validation, bounded chunked reads, owner-only permissions, atomic replacement, and erase mechanics between actor-isolated stores.

`UserDictionarySettings` owns the separate explicit phrase dictionary and uses `UserDictionaryStore` for local persistence and file import/export preparation. JSON imports validate all phrases, merge into a copy, preserve existing content/pin settings, and apply only if no intervening edit/clear changed the revision. Capacity errors leave the entire import unapplied. Storage and import/export errors remain distinct so a later successful save cannot hide a failed import. Phrases retain until explicit deletion, independent of learning. Cached code/identity indexes support direct full/prefix matches and intermediate lattice nodes; any derived path containing a personal node is excluded from automatic learning and prior-word context.

The package compiles the same storage actor and observable settings models as the app under separate test targets. Conditional imports bridge package modules without duplicating implementations. SwiftUI views remain in the app target.

## macOS integration

`SIApplication` starts an AppKit application. `AppDelegate` retains one `IMKServer` for the process lifetime. `mac/Support/Info.plist` names the connection and the stable Objective-C controller class `SIInputController`; it declares a background input method with one input source and no mode dictionary. The bundle and source identifier is `com.caterm.inputmethod.si`, including the `.inputmethod.` segment used for InputMethodKit discovery. `TISIntendedLanguage` is `en` so SI is discovered under English; its character repertoire still includes Latin and Simplified Chinese scripts. This system classification does not choose an active language inside SI. Showing Settings changes the process activation policy to accessory so the background declaration does not prevent displaying the settings window.

The local installer builds Release by default (`./scripts/install.sh Debug` explicitly opts into an unoptimized debugging build). It calls `TISRegisterInputSource` after installing the signed bundle, then queries only SI's bundle ID (including disabled sources) and requires exactly one selectable keyboard input method. It never enables/selects an input source. `--check` performs only the verification query. Existing `com.caterm.si` installations are backed up and replaceable by the installer. `SettingsDefaults` deliberately retains the original `com.caterm.si` domain for language, punctuation, and learning consent; archives remain at their existing Application Support paths. No consent is reset or inferred by the bundle-ID correction.

`scripts/reinstall.sh` explicitly opts into stopping the current user's exact-name `SI` processes with SIGTERM, waiting up to five seconds before SIGKILL and another bounded wait. It then delegates to the unchanged installer, retaining both running-process checks and the existing backup/rollback path. A restarted process can still cause installation to abort. It does not select/enable input sources or force logout; pending composition and unsaved learning may be lost when stopping SI.

`SIInputController` adapts key events to the core and maintains marked text in the client. It owns one `CandidateSelection` and one nonactivating AppKit `CandidatePanel` per client. Number labels, highlighted rows, arrow/page navigation, Space confirmation, and mouse clicks use the same selection/page state. A composition starts collapsed, with five choices per horizontal page; expanding shows nine choices per vertical page. Switching layout preserves the selected candidate and recomputes its visible page/number; ending the composition resets expansion. Row labels remain presentation data; only validated candidate text is committed. Objective-C callbacks lack Swift actor annotations. The UI callback boundary uses `MainActor.assumeIsolated` explicitly; this relies on InputMethodKit delivering those callbacks on the main thread. Non-Sendable Objective-C callback arguments are captured using narrowly scoped `nonisolated(unsafe)` locals, and the controller explicitly declares `@unchecked Sendable` while its mutable state stays main-actor isolated. This boundary must be exercised during manual integration checks.

The input window features the engine's first two nonliteral whole candidates, then up to seven prefixes ranked across spans, followed by unfeatured results in their original engine order. It limits this presentation list to 27 candidates (three expanded pages or six compact pages), reserving the engine's first candidate for each single-language/mixed identity and the exact literal fallback before filling the remaining slots in presentation order. Retained candidates keep that order; lower-ranked alternatives are omitted from the input window. Ties retain engine order. `InputSession.presentationScore` supplies the same consumed-spelling, token, whole-input and eligible context scoring for prefix promotion, honoring the session's learning/secure-input configuration. The engine, Settings preview, immutable candidate identities and exact commit text remain unchanged. This is a bounded display shortlist, preserving each matching language identity, and does not add semantic ranking. The cap does not change engine search budgets or computation cost. Navigation and mouse selection both refer to the permuted client-local list.

The controller consumes navigation and number-selection events while composing. `CandidateSelection.action` maps event key codes/characters to moves or numbered choices; both the view and commit lookup read the resulting page. There is no `IMKCandidates` instance or dependency on its selection-key display, identifiers, or callbacks. Out-of-range row numbers do not commit another candidate. Shortcuts retain literal passthrough, and outside composition these keys pass through. Candidate edits/reset invalidate the previous selection. Mouse buttons return candidate identities and use the same current-candidate validation/learning path as digit keys.

The panel never becomes key/main, preserving the host's input focus. `CandidateAnchor` queries the SDK's inline-relative UTF-16 `attributes(forCharacterIndex:lineHeightRectangle:)` at the composition start, then at the current composition caret if necessary, without reading surrounding text. It rejects invalid/offscreen geometry and caches only the last valid rectangle for that client/composition. Commits, cancellation, and deactivation clear it. With no valid query or cache, the panel hides rather than inventing a screen-center position. `CandidatePlacement` uses AppKit screen points directly, without a Retina multiplier or coordinate flip, places below the anchor or above when necessary, and clamps to the containing screen's visible frame. Page buttons update the same model; wheel and trackpad scrolling are ignored in both layouts. Buttons expose candidate text/language/number and selected state through accessibility; clipping long labels does not alter committed text, which remains available in tooltips. The package's `SIPresentation` target compiles the same selection and AppKit view sources for focused regression checks; this is not a second engine.

`CandidateStyle` supplies dynamic warm-neutral light and dark palettes. The selected candidate uses a soft peach/umber background with an orange number and ordinary adaptive label text. The system Increased Contrast preference strengthens the card border and outlines the selection. The default 36-point-high strip lays out up to five 28-point candidate buttons horizontally and reserves a trailing expansion chevron with a subtle divider. Each button keeps a compact gap between its number and candidate labels and fits its text and source symbol, capped at 280 points. Extra retained window width does not stretch compact buttons; narrower screens proportionally shrink them without overlapping the chevron. Text-cell insets are included in width measurement; labels with too little room to draw a complete glyph hide rather than clipping through a symbol. Full text remains in accessibility and tooltips. Expanded mode uses a vertical card within 180–600 points, with a collapse chevron and a footer whose page count/previous/next controls appear only for multiple pages. Ordinary language descriptions are hidden visually. Compact prefix/personal/literal/verbatim hints use small symbols; expanded hints retain text such as `First N`. Language identity, full text, exact consumed-input descriptions and selection state remain available in accessibility labels and tooltips. Both layouts retain pending geometry, refresh rows on accepted provisional delivery, and disable selection, paging and expansion until full results arrive. Horizontal and vertical scrolling never change pages or selection. Clipping labels never changes committed text.

`scripts/generate-icons.swift` produces `InputSourceIconTemplate.tiff` on a 16-point canvas with 16×16 and 32×32 pixel representations. The rounded badge is opaque, while the SI glyphs are cut out with destination-out blending. `TISIconIsTemplate` is true, allowing macOS to tint this alpha mask for menu-bar appearance and selection without flattening opaque lettering and background into a solid block. There is no separate alternate color bitmap. The new resource name distinguishes it from the former full-color assets; installed sources retain their identifiers, connection, and language settings. Core Text glyph bounds, rather than the font's full line box, determine centering. Both representations carry the same logical size, avoiding a 32-point icon in system input-source rows. Resource previews and bundle checks do not establish actual menu-bar rendering; verify the installed update in the login session.

App Sandbox is disabled because the legacy InputMethodKit server uses interprocess connections with text clients. SI does not request Accessibility or Input Monitoring permissions and does not install a global event tap. `LSUIElement` keeps the input-method process out of the Dock. Closing Settings does not terminate the server.

`LanguageSettings` is main-actor-isolated and observable. It persists enabled-language booleans and the punctuation behavior in the stable `com.caterm.si` defaults domain. Both languages default to enabled; absent or unknown punctuation preferences default to Keep Composing (`asTyped`); explicit saved smart/confirm policies remain selected. Settings take effect when the next key event refreshes a composition. Disabling all languages leaves literal input available. Shift and Caps Lock do not select a language mode.

The Xcode Run scheme passes `--settings`; normal system launches keep the process in the background. The installed app exposes Settings through the input menu and on reopening the app.

## Distribution tooling

`scripts/package-dmg.sh` and `scripts/release.sh` share `scripts/release.py` and the existing SI Xcode target. Packaging builds Release for Universal or a selected architecture, signs a staged copy, and wraps it in a native Installer package inside the DMG. `scripts/installer/Distribution.xml` restricts installation to the current user's home domain and requests `RequireLogout`; macOS Installer owns the final Log Out button and normal save/cancel handling. Its preinstall script rejects a running SI or foreign bundle and copies existing SI to the established backup directory. Bundle relocation is disabled so other built/installed copies cannot redirect the payload. Native strict-ID matching is disabled only to permit the legacy `com.caterm.si` migration; preinstall explicitly permits only that ID and the current SI ID. Publication requires Application/Installer signing, notarization and a clean checkout, includes corresponding committed source, and verifies anonymous R2 downloads before conditionally promoting an independent SI architecture channel. All build/release files stay under `.build/` by default. Running packaging does not install, launch or log out; installation/logout requires the user to run the package and click through macOS Installer. No in-app updater or network processing is added. See [RELEASING.md](RELEASING.md).

New publications increment the Xcode patch/build metadata after preflight and commit only that version file, keeping the built app and corresponding source archive tied to the same revision. An architecture-local pending marker under `.build/` preserves the chosen version for failure retries. Successful publication clears the marker; `--no-bump` explicitly reuses the current version for another architecture or a retry without local state. Dry-run/local packaging do not mutate versions or Git history.

## Extending language support

1. Add a stable language identifier and English display name to `InputLanguage`.
2. Implement a `CandidateProvider` with local, deterministic behavior and licensed data.
3. Register the provider in `CandidateEngine` and expose its enabled preference in Settings.
4. Test ambiguous sequences, disabled-language filtering, deterministic ranking, literal fallback, and composition resets.
5. Document dictionary provenance, performance characteristics, and limitations.

`PinyinDecoder` indexes the merged maintained Chinese entries and composes readings in a bounded lattice. Apostrophes constrain syllable boundaries rather than being discarded. Lookup supports stored-reading prefixes, full/initial variants, final-word completion, and personal nodes. Unknown spans preserve their source spelling only when no exact non-abbreviated complete path exists. Search keeps 12 base paths and, where relevant learning applies, up to 12 additional personalized paths per language-combination, last-language, and verbatim state per position. Direct results remain separately available. Personal-node fanout and constructed-output size are bounded. Words sharing syllables share reading variants and boundaries; exact indexes store reading IDs, while full-spelling completion uses binary-search ranges without eager per-prefix entry copies. Terminal states distinguish complete and completion paths with fixed per-state budgets and compact large batches using bounded ordered selection after scoring. Chinese abbreviation paths inside a known exact English word also receive no split-token learning bonus. English casing follows typed case. The vocabularies are shared across sessions. English uses generated, pinned multi-source data and a shared compact ASCII Trie. Its nodes hold child bitmaps, packed child IDs and contiguous ranges into sorted entry metadata. The first default engine prepares the Trie and cached canonical/initial-capital/uppercase text, lengths, completion scores and continuation costs; later engines reuse them. Mixed English lookup advances one cursor per source start, stops at missing letters or internal apostrophe boundaries, and reuses the final cursor for completion. Static metadata carries no personalized scores or user input. These structures are rebuilt after process restart rather than serialized. Maintenance commands download upstream sources separately, while the app performs no vocabulary file access or downloads. No system dictionary is copied. See `docs/ENGLISH_VOCABULARY.md` for generation, overrides, provenance and scheduled audits. Chinese generated data and its retained source notices are described in `docs/CHINESE_VOCABULARY.md`. See `docs/DICTIONARIES.md` for limits.

Repeated sorting of long shared text prefixes was a measured hotspot. Paths composed only of ASCII and unified CJK ideographs (U+3400–U+4DBF, U+4E00–U+9FFF) carry a conservative flag permitting bounded UTF-8 byte comparison. These scalars stay in NFC through concatenation, matching the [Swift standard library's NFC ordering](https://github.com/swiftlang/swift/blob/main/stdlib/public/core/StringComparison.swift). Other text retains Swift's canonical comparison. Path identity equality still compares original text; hashing uses canonical UTF-8 bytes, normalizing the complete text when needed so equivalents across the fast/fallback paths share a hash. Commit text is never normalized. Combining marks, Hangul Jamo, emoji, variation selectors, and compatibility ideographs remain outside the comparison fast path. Buffer reads remain scoped to `withUTF8` and bounded by both lengths.
