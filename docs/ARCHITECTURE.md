# Architecture

## Product contract

SI exposes one macOS input source. Settings contain a set of enabled languages, not an active language. Every enabled provider is queried for the current composition. Matching candidates coexist; ambiguity is a choice for the user rather than a reason to switch modes. Literal input is always offered.

## Data flow

Runtime ranking uses the packaged dictionaries and shared word, spelling and language-transition costs.
Opted-in Personal Learning retains its existing frequency and exact-choice preferences.
Production ranking groups whole candidates before prefixes and reranks Chinese
lexical tokens with a local KenLM model when available, including Chinese
segments in mixed results. The same configuration runs in Debug and Release.
Live-host validation remains outstanding.

```text
Host application key event
  → SIInputController
  → client-local InputSession and immutable CandidateRequest
  → full/provisional background workers
  → CandidateEngine
  → Swift ChineseDecoder + English lookup + shared English/mixed lexical search
  → language-aware merge by shared effective score + exact literal fallback
  → revision-checked CandidateResult → InputSession
  → client-local selection/page state → nonactivating AppKit candidate window
  → committed text in the host application
```

## Interface localization

`mac/SI/Localization/Resources/{en,zh-Hans}.lproj/Localizable.strings` provides the same English source keys and Simplified Chinese translations to SwiftUI and AppKit. The app uses the main bundle and native macOS app-language negotiation, with `en` as its development language. SwiftUI literal labels use native localization; `L10n` resolves dynamic labels, errors and format arguments. The package builds the same helper/resources as `SILocalization`, using `Bundle.module` for tests. Language changes take effect on a normal process restart; no extra language preference, input mode or keystroke shortcut is introduced.

Localization stays outside `SICore`. Stable language identifiers, core display-name/label metadata, candidate identity, ordering and exact commit bytes are unchanged. Settings localizes the core language/punctuation descriptions at presentation; `CandidateDescription` derives localized candidate labels from structured metadata. User text, phrase codes, application names/identifiers and archive contents are never treated as translation keys. E/C/A punctuation badges keep their existing identifiers while tooltips and accessibility descriptions are translated. No input or personal data is added to localization resources.

## Chinese engine migration

The current worktree replaces production Chinese decoding with a native Swift adaptation of MSIME. Debug and Release builds pass after the first validation round; regression and quality failures remain documented in `docs/VERIFICATION.md`. It has not been profiled in host apps. `docs/IMPLEMENTATION_PLAN.md` records remaining correction-path, optional neural and quality-parity work. No Rust library, foreign session state, user journal, network inference or telemetry is linked.

`PinyinDecoder` is the shared facade for app and package. Production and injected Chinese lexicons feed the same `ChineseDecoder`. `ChineseSyllables` derives the primary minimum-segment cut and bounded complete alternatives from the pinned syllable inventory; explicit apostrophes constrain cuts. Canonical umlaut aliases are applied per syllable. Existing `PinyinInput` maps normalized letters back to exact source-character boundaries, including ü, u: and trailing separators.

`ChineseLexicon` performs exact, trailing-prefix, mixed-initial and longer-word lookup over one read-only SQLite resource. Injected lexicons implement the same lookup in memory. Chinese and English use the same versioned SQLite schema, weight metadata and `LexiconDatabase` reader. The database and prepared statements are protected by one lock; this explicitly documented synchronization is the basis for the database wrapper's sendability, independently of InputMethodKit callback assumptions. The immutable SQLite URI avoids journal writes and file-version polling. Statement lifetime never escapes the lock. Resource initialization is lazy on candidate workers, not performed by constructing a deferred client session.

`ChineseResources` resolves the same bundled resources in the Swift package and application. The historical `ChineseNgramTable` reader remains for format fixtures; archived MSNG tables are not loaded or bundled. SI-maintained category CSVs under `Data/Vocabulary/{chinese,english}/`, plus Chinese phrase/verse CSVs under `Data/Vocabulary/chinese/phrase/`, compile through `scripts/csv_dictionary.py` into these existing resources. The Chinese collection contains the Wanxiang base, ten imported categories named after the upstream files and seven earlier local category CSVs and a separately reviewed corpus category; English has base, movie, domain, SI-authored technology and common-word categories. The common-word category restores `a` at the default editorial weight 10 and survives upstream base conversion. The technology CSV uses the same automatic discovery, key generation and base-precedence rules, without runtime category state. The 1,209-entry domain category merges the 304 SI-authored names and the 1,000-domain Radar bucket, preserving all existing weights and retaining source snapshots/checksums and separate CC BY-NC 4.0 attribution. It supplies complete public hostnames with identical lowercase text/readings, preserving dots, hyphens and digits. Standalone suffixes are excluded. The shared English trie uses an ASCII-ordered 64-bit child mask for letters, digits, dot and hyphen; direct/preview lookup follows literal domain prefixes. Domain readings are validated separately from alphabetic word/title readings and retain the same SQLite schema; numeric-leading domains use the first alphabetic byte for the existing table bucket. This adds no URL mode or runtime network access. The paired movie review catalog covers 400 selected films from 2007–2026; only category CSVs feed runtime compilation. These are maintenance groups without runtime category weighting or language switches. New category files are discovered automatically. The corpus review adds 266 explicit text/reading pairs with evidenced editorial weights, capped at 5,000, and eight bounded edits to authoritative base rows; other local category weights and user adjustments remain intact. Offline HanLP observations, manual exclusions, source notices and correction evidence are retained outside the runtime CSV columns. No model is loaded by the app. `Data/Vocabulary/meta.json` indexes bootstrap source metadata and attribution once, outside the rows. CSV rows contain only exact text, explicit readings and integer weights. Pinned base identities take precedence over category copies, preserving Wanxiang weights and English casing; imported categories then override legacy copies absent from base, with maximum-weight merging within each tier. Internal row IDs follow UTF-8 binary reading/text order, so row reordering and nonbase category renames do not change ties; moving an overlap into or out of base can change its authoritative weight. English title keys omit output punctuation/spaces and spell digits individually, retaining 1–64 lowercase ASCII letters. The immutable English trie uses stored keys and key lengths rather than display text. Entries with the same key are ordered once at initialization by descending weight, then canonical row ID, so direct lookup retains weight priority for same-key variants. Distinct outputs sharing a key retain separate terminals and mixed-search edges; the representative terminal uses highest weight with content-order ties. Base English spelling shadows case-only category copies; case conflicts among nonbase additions are rejected. Invalid rows, conflicting English casing and incompatible metadata fail before publishing outputs; two-language builds validate both before replacing either. Current Wanxiang source pins and the report are in `Data/Vocabulary/Wanxiang/` and indexed by `meta.json`. The independently written `wanxiang_dictionary.py` explicitly fetches locked data and converts both bases and ten upstream categories offline, without touching preexisting category files. Historical wordlists, wordfreq imports and JSON overlays remain removed. Full notices/licenses remain under `Data/Chinese/MSIME/`, `Data/English/licenses/` and `Data/Ranking/wordfreq-3.1.1/`. The converter excludes private-use outputs; retained local categories and the generated resource also pass the private-use exclusion check. No runtime download path exists.

The Chinese lattice spans syllable positions, with up to seven syllables and 32 lexical rows per span. For an uncorrected complete primary reading, up to 32 complete cuts with the same minimum syllable count share this lattice, including inputs longer than four syllables and cuts constrained by apostrophes. This bounds complete segmentation alternatives without rewarding extra syllables. Each edge and path carries exact normalized-source offsets: only matching offsets can join, repeated spans are looked up once, and prefix scoring/confirmation uses each path's actual source boundary. Minimum-cut dynamic programming runs before bounded enumeration so longer cuts cannot exhaust the 32-cut budget. Corrected aliases and incomplete readings retain their primary-only sentence behavior. Saved personal codes can add independently bounded spans. The continuation search retains a 32-path base beam and a separate bounded personalized lane where existing token preferences apply. `ChineseBeam` streams incoming paths through the same heap selection as MSIME, and `ChinesePathOrdering` implements its libc++ introsort tie movement for terminal selection. A secondary text/arrival sort would change equal-score survivors. Base arithmetic stays in natural-log units through search and terminal selection; SI preference boundaries convert to bits. All decoders use `CandidateScoring`: a shared 1.05 log-frequency coefficient, a 20-nat word insertion prior, and a two-nat Chinese-character cost instead of upstream's `ln(1e6)`. The old Chinese per-syllable score offset is removed. Per-syllable spelling observations and the same one-bit initial/synthetic continuation language costs enter both Chinese and lexical search. This intentional local scoring change reduces the bias toward low-frequency cross-boundary fragments that absorb a natural standalone character. A small character cost remains to discourage excessive splitting; it is not a corpus probability. Six distinct terminal sentences per lane are retained. No corpus context or sentence-opening correction is applied. Prefix presentation uses only consumed spelling; pending-suffix costs are excluded. All six retained alternatives per lane are emitted, deduplicated across base/personalized lanes. Automatic-confirmation requests use the same alternatives to suppress disputed boundaries without changing candidates or scores. Its word score and explicit candidate policy remain a heuristic objective, not a calibrated posterior.

Whole-input and eligible previous-word preferences participate before terminal presentation limits. Independent base terminal paths remain available. Prefix choices use a separately bounded pool before continuation selection, score against the consumed spelling, and preserve two distinct composed choices per consumed span. Exact complete-syllable single-character choices bypass the 24-word prefix pool. Provisional/full direct and first-syllable prefix lookup supplements its normal limits with all exact dictionary characters; initial/completion and constructed-sentence searches retain their existing bounds. Strongest derivations retain single-lexical-unit evidence when identities coincide. Any path containing a personal phrase is excluded from token, whole-input and contextual learning. Explicit personal phrases continue using SI's existing store and retention/deletion rules rather than MSIME's archive.

Saved codes do not replace the default Chinese segmentation. The canonical lattice retains compatible saved nodes, while a separate personal-code cut can supply additional paths containing a personal node. That supplement cannot contribute ordinary Chinese alternatives or automatic-confirmation evidence. Direct saved prefixes use the existing sorted code index independently of the 12-node constructed fanout, and every saved node respects typed apostrophe boundaries. Constructed Chinese personal nodes use MSIME's 10,000 initial insertion prior, with the retained one-bit pin preference; this is a prior, not measured word frequency. No new retained personal data is introduced.

Exact Chinese words, alternative complete readings, sentences and completions compete by effective score. Fixed spelling aliases, bounded retroflex-initial splits and sparse lookup fallbacks retain source boundaries and score their actual typed reading. CandidateEngine deduplicates using language/text/source-span identity and globally sorts whole and prefix choices by the lexical/preferences score plus five points per matched source letter or digit. Coverage uses only consumed spelling, counts ü/v/u: equally, ignores separators/punctuation and gives verbatim-containing paths no reward. It neither predicts a suffix conversion nor rewards output length or lexical-unit count. Same-span lexical alternatives retain their original ranking; length is a soft reward, not an absolute ordering key. Exact pinned personal phrases retain their explicit override; language categories have no front-position privilege. Both CSV bases and ten separately classified Chinese dictionaries now come from pinned `rime-wanxiang-data`: Chinese uses `zi`, `jichu` and `duoyin`; English uses `en`. Stored base weights retain the upstream scale, with [documented SI editorial weight adjustments](../Data/Vocabulary/chinese/README.md#si-editorial-weight-adjustments). The `si-wanxiang-weight-v1` resource contract has reference mass one; the reader rejects the retired relative-frequency contract. Local category texts/readings remain intact; their weights are 10, with the same default for new additions. English casing and membership follow the new source, with explicit supported-format exclusions. The old MSIME/wordfreq bootstrap records remain historical provenance. Both languages now use SI-owned CSV categories and source-level provenance metadata; their historical source records are inline metadata, with old word/frequency snapshots removed. English loads database rows once on a candidate worker and builds its existing immutable trie, with no generated English word/frequency Swift tables or per-key database load. Ordinary maintenance builds do not reimport upstream lists or recalculate existing weights. Shared costs make full scores comparable heuristic objectives; they are not calibrated probabilities. `LexicalCompositionDecoder` now reuses the bounded English continuation, terminal/prefix selection, canonical identity and learning machinery for mixed paths, querying the same ChineseLexicon directly instead of constructing another vocabulary/model per event. The former compiled Chinese reading tables and character-boundary model are not restored. Pure Chinese sentences continue through ChineseDecoder.

`LexicalCompositionDecoder` uses normalized source-letter positions for bilingual word edges. Complete Chinese syllables are enumerated under explicit apostrophe constraints, with at most seven syllables per word, 32 readings per end, 256 visited readings per start and 32 lexical rows per reading. Per-request lookup results are reused. English exact spans and final completions walk the existing trie and retain source casing. Chinese, English and mixed paths all use `CandidateScoring` word and language costs. Each English dictionary token adds three nats to its shared lexical cost; a Chinese single-character token retains its two-nat addition. English direct/preview lookup, completions, sentence edges and prefixes reuse the same immutable entry cost. Personal-code priors and unrecognized verbatim costs remain unchanged. Chinese adds its per-syllable spelling channel and English its word-prefix channel. The synthetic language-transition prior remains explicit. It does not add spelling aliases or initial-only Chinese edges.

Lexical output inserts one space between adjacent English edges in both English-only and mixed paths. Chinese/English transitions also insert one space; adjacent Chinese words concatenate without a space. The same rule applies to provisional/full candidates, projected suffixes and continuation joins. Source traces retain both emitted and unspaced UTF-8 offsets; compatible lexical prefixes use emitted offsets, including spaces, for exact output alignment. Paths containing personal/verbatim nodes retain their existing exact concatenated output. Candidate identity and commits use the emitted text, and both representations respect the 4,096-byte output bound.

The existing twelve-path state beams, separate base/personalized selections, two protected full spellings, bounded prefix pools, personal fanout and 4,096-byte output limit remain. Exact lexical English boundaries prevent token learning from promoting split-word alternatives. Paths containing personal/verbatim nodes never receive learning/context effects. Mixed results carry no automatic-confirmation trace. The engine queries every enabled lane, preserves language-aware identity, and ranks their whole and prefix results together by effective score. Mixed results stay in the engine and qualify for the window through the first four coverage-adjusted ranked choices, sharing that eligibility with Chinese/English hypotheses and receiving no identity reservation. Direct English words and English/mixed sentence tokens use the same word/spelling cost. Explicit personal phrases use the shared 10,000-weight prior and code-spelling cost; unpinned phrases compete by score and no longer inherit a dictionary-size-dependent direct score. The engine retains all emitted results, with exact literal fallback.

`CandidateEngine` ranks each candidate using only the spelling it actually consumes. `InputCandidate.inputScore` equals its base `rankingScore`; no suffix projection, unknown-remainder penalty or additional prefix-confirmation cost is applied. `LearningProfile` adds the capped frequency/token maximum and eligible previous-word bonus for the consumed spelling, without scaling by total composition length. This same rule applies before Chinese/lexical prefix presentation limits, in provisional/full merging and in `InputSession.presentationScore`. The engine does not query providers for suffix lookahead. Within a production coverage group, short words and sentences compete by score. Whole candidates precede prefixes, and longer prefix spans precede shorter ones. Saved base scores, preference units and storage limits are unchanged.

Source traces and confirmation boundaries retain exact source/output alignment as decoder evidence; they do not add scores from another candidate or the pending suffix to an explicit prefix. `CandidateLanguageBoundary` still records endpoint languages for lexical spacing and transitions within constructed candidates. Full sentence construction, base/personalized beams and the 4,096-byte output bound remain. Only confirmed consumed spelling can train vocabulary; hypothetical suffix words are never persisted.

`InputSession`, `LearningProfile` and `UserDictionary` remain UI-independent value types. One session owns its composition buffer, character-aware caret, recent chosen-word context and revision. Deferred edits retain exact literal spelling immediately. Only a result for the current revision, configuration and client can update candidates; final delivery rejects later provisional delivery. Candidate confirmation resolves full results before selecting. Return, cancellation, shortcuts and focus boundaries preserve or cancel exact spelling without waiting. Neither worker writes personal archives.

The shared spelling channel assigns sixteen times the geometric endpoint weight to a complete English word or Chinese syllable, then normalizes over its supported prefixes. Completing the last missing letter improves the spelling score by five bits. Chinese applies it per syllable independently of word segmentation; English direct lookup, cached preview and sentence edges use the same channel. This favors bilingual `ma` → `吗` without a language reservation or input-specific override. It also increases competition from fully spelled English word sequences against unfinished single words; see [ranking tradeoffs](UNIFIED_RANKING.md).

`CandidateSelection` uses a 27-choice ordinary budget plus dictionary-character retention, preserving language-aware candidate identities and exact input without language reservations. Ordinary whole/prefix and word/character candidates compete by coverage-adjusted score; the first four ranked choices may contain constructed hypotheses, while later ordinary choices are single lexical units or explicit personal/punctuation choices. The retained candidates keep engine order without protecting a language leader. The engine retains full results. Prefix commits consume only validated exact source boundaries, keep the remainder marked/editable and avoid adding a space while a remainder exists. Candidate labels never become committed text.

Settings contains language, typing, direct-input, Personal Learning, Input History, personal-phrase and update controls. It does not run candidate searches.

`PunctuationCandidates` supplies a fixed local table of English/Chinese alternatives for common ASCII punctuation. The shared engine includes these alongside direct provider and personal matches only when its explicit punctuationCandidatesEnabled option is enabled; this option defaults to false. Exact literal spelling is retained. A single trailing mark can be attached to complete word/sentence choices from the same engine; partial and incomplete choices are excluded. Repeated trailing punctuation does not recurse or expand combinations. Apostrophes after existing input retain their syllable-boundary meaning. `InputCandidate.punctuationLanguage` distinguishes punctuation variants independently of a preceding word's language and participates in cached identity. Explicit isPunctuation metadata also marks the literal fallback for badges and acceptance-spacing behavior, rather than inferring the enabled feature from its text. These variants inherit personal/verbatim exclusions, carry no automatic-confirmation evidence, never train vocabulary/context and never append an acceptance space. Constructed output remains bounded to 4,096 UTF-8 bytes. Full and provisional generation share this path; original input and stale-result validation remain unchanged.

With Show punctuation candidates and a language enabled, the controller starts marked composition for mapped punctuation even when the buffer is empty. The switch is off by default; when off, all punctuation outside composition passes through. Other symbols pass through outside composition. During composition the existing `PunctuationBehavior` policy still decides whether a key remains editable or confirms a candidate. Compact and expanded rows show small E/C badges immediately after punctuation text, with A for the As Typed literal fallback; tooltips and accessibility retain the full description. Badge letters use Core Text glyph-path bounds to center their visible ink horizontally and vertically, independently of NSTextField baseline padding. Only the selected text is committed.

## Candidate presentation

`MarkedTextPresentation` projects the session's exact buffer into host marked
text using source-character cuts from the highest-ranked whole nonverbatim
candidate. Chinese lexical traces carry source-only syllable cuts separately
from output-aligned confirmation evidence; English trace nodes delimit words.
Incomplete direct Chinese readings retain their typed cuts as display metadata
without creating confirmation evidence. The projection inserts visual spaces,
preserves original bytes/casing/apostrophes, and maps the character caret to the
displayed UTF-16 offset, including those spaces. The controller uses that offset
for marked selection and inline geometry. Editing, commits, learning and history
continue to use the original session buffer. Pending searches have only current
literal spelling until revision-checked hints/full results supply segmentation;
identical marked text/selection is not resent. Prefix-only candidates do not
invent segmentation for an unconsumed remainder.

`CandidateSelection` owns one client-local engine shortlist, selected index and
page. Compact rendering shows one numbered row; Down expands the same ranking
into a grid. Space, numbers and mouse clicks confirm the same candidate IDs, and
the displayed global first choice stays neutral for Personal Learning. Pending
engine searches disable stale rows until revision-checked results arrive.

At startup the app opens a verified local model on a background task.
`CandidateRankingPool` reuses the engine's winning lexical traces, resets the
LM state at language boundaries and applies the new scores before shortlisting.
English LM weight is zero. The production English insertion cost is 28 bits per
dictionary token, including tokens in mixed candidates. Request snapshots carry
the model and configuration, and old requests cannot publish after session
reconfiguration. Previews and synchronous selection fallback use the production
dictionary scores without querying the model. Secure event input uses legacy
ranking. Release packaging stages the verified model inside the signed app.
The loader prefers that resource and retains the App Support model as a fallback
for source builds. Ranking reads no host text. `LanguageSettings`
clears the retired AI and development ranking preferences without changing
languages, direct-input rules or recording consent.
See [the production model record](../README_kenlm_train.md#production-kenlm-ranking).

## Automatic prefix confirmation

`LanguageSettings` persists a separate, initially disabled automatic-confirmation option. Its in-process configuration generation also changes when languages or punctuation/confirmation settings change, invalidating evidence even if a setting is toggled away and back between input events. Secure event input disables the option at the controller boundary independently of learning consent.

When enabled, full `CandidateRequest` generation captures transient `ConfirmationBoundary` evidence from the existing lattice: exact source-character counts (including ü/u: normalization and trailing separators) and cumulative output UTF-8 byte counts at up to eight leading, exact Chinese lexical nodes. Immutable shared trace tails bound per-path evidence without copying boundary arrays on each expansion. Capture stops at abbreviation, completion, personal, verbatim or English edges; full results retain earlier exact boundaries. Capture is disabled for provisional searches and ordinary engine callers. Evidence does not affect identity, scores, pruning, lexical presentation or output bytes.

On the background worker, `AutomaticConfirmation.prefixes` compares the leading whole Chinese candidate with every whole alternative within three ranking-score points, including eligible other-language competitors. This is a relative-score band, not a calibrated confidence probability. A proposed prefix must have identical committed bytes and source/output boundaries on every competitor; no textual-prefix or syllable-count guess substitutes for alignment. Mixed/personal/verbatim leaders, uppercase spellings, malformed output boundaries and non-Pinyin symbols do not produce proposals. An exact English word of at least four letters starting at a leading Chinese lexical boundary also suppresses proposals, independently of enabled languages; this protects tails such as `title` from being treated as Chinese-only spelling. Explicit syllable separators constrain this check. Literal fallback remains present but is not statistical evidence against every conversion.

`InputSession` retains at most eight client-local prefix observations. Only accepted full results advance stability, once per distinct appended spelling; pending, provisional, stale and cross-session results cannot confirm. Continuous confirmation requires two observations, six additional source characters since the first observation, at least four remaining output characters and eight remaining normalized letters. Pause confirmation requires at least 1.8 seconds since input, 0.6 seconds since the observation, a prefix of at least two output characters, two remaining output characters and four remaining normalized letters. Both use the same consensus proposals and complete lexical boundaries. Editing/navigation suspends evidence; only fresh end-of-buffer typing can restart it. Configuration, reset, commits and host boundaries invalidate evidence and the timer revision. A prefix commit resets observations, so a timer cannot repeatedly drain a stationary composition.

`SIInputController` attempts continuous confirmation on accepted result delivery. Its single cancellable, weakly captured main-actor pause task rechecks session revision, current client, settings and secure input before the same `automaticallyConfirm` method. Neither path synchronously resolves a search. `.automaticConfirmation` has zero learning weight and never creates previous-word context; no new persistence or surrounding-document reads are introduced. The ordinary prefix commit/marked-remainder path handles insertion exactly once without an English space. Already committed text uses ordinary host editing; there is no cross-host automatic reconversion/undo contract. Native focus/timer delivery remains an integration check.

## Personalization and storage

`ApplicationMemorySettings` is the sole automatic-learning settings model. The retired global `PersonalizationSettings`, its Settings views and `LearningStore` are removed from the app and package. Launch/termination prepare or flush app memory, explicit phrases and the independent Input History store; input uses a shared global profile when learning is enabled and input is not secure. Disabled or secure clients use base ranking. No disk I/O or dictionary initialization runs in the keystroke handler.

The UI-independent `LearningProfile` and `LearnedPreference` models remain shared ranking primitives for Personal Learning. Single-language frequency records can influence whole/prefix and eligible internal tokens before bounded limits, preserving base/personalized search beams and the shared 32-point cap. Chinese single-character outputs do not transfer into other compositions. Core contextual-ranking/session APIs remain available to library fixtures, but the application does not enable, store or expose previous-word pair learning. Old global archive schema versions are no longer loaded or migrated.

`PrivateArchiveFile` shares regular-file validation, bounded reads, owner-only permissions, atomic replacement and erase mechanics across the remaining storage actors. App memory provides an actor-isolated existence/deletion operation for the retired `preferences-v1.json` path without decoding its contents. Settings exposes explicit deletion with independent progress/error feedback. Old consent flags are ignored and removed only with that deletion. Existing files are not erased or assigned to guessed app scopes; the inactive old archive receives no automatic retention maintenance.

`UserDictionarySettings` owns the separate explicit phrase dictionary and uses `UserDictionaryStore` for local persistence and file import/export preparation. JSON imports validate all phrases, merge into a copy, preserve existing content/pin settings, and apply only if no intervening edit/clear changed the revision. Capacity errors leave the entire import unapplied. Storage and import/export errors remain distinct so a later successful save cannot hide a failed import. Phrases retain until explicit deletion, independent of learning. Cached code/identity indexes support direct full/prefix matches and intermediate lattice nodes; any derived path containing a personal node is excluded from automatic learning and prior-word context.

### Personal Learning

`ApplicationMemory` contains global `ApplicationVocabularyEntry` records keyed by normalized consumed spelling, language/mixed identity and output, without application identifiers. Each record retains a noncontextual `LearnedPreference`, aggregate use/correction counts, base score, lexical-unit evidence and optional latest deliberate-selection time. Every eligible confirmation increments usage; only explicit nonfirst choices update the remembered choice and correction count. Every third correction still adds one frequency point, up to 32, stored as `exp2(bonus / 12) - 1`. `LearningProfile(retainsIndefinitely: true)` disables age expiry and strength decay for this product profile; the default library policy remains available for historical fixtures. Zero-strength usage-only rows inject no candidates; one correction can inject its saved candidate immediately. Literal, personal/verbatim, punctuation and automatic/delimiter commits never train. No sentence-token decomposition is saved.

A bounded spelling-to-record index maintains one latest deliberate choice per normalized spelling. A new correction clears the former choice's selection marker, even when wall-clock timestamps tie, without deleting its aggregate counts or frequency strength. `ApplicationMemorySnapshot.preferredCandidateID` resolves the whole normalized input against enabled languages. The shared engine's final and provisional merges place this ordinary whole candidate after explicit personal pins and before score-ranked alternatives, leaving all other candidates in their deterministic score order. Prefixes, shorter spellings and longer inputs never gain forced placement. A prefix confirmation can supply the remembered choice only when its consumed spelling is subsequently typed alone. Exact literal input remains explicit and language-aware identity is unchanged. Forgetting a selected entry restores ordinary ranking, without reviving an older selection marker.

`ApplicationMemorySettings` owns default-off global learning consent and one cached immutable snapshot. Learning settings/snapshot/record APIs have no app parameter or exclusion list. The retired `applicationMemory.vocabularyExclusions` key is removed without changing existing learning consent. The controller still reads the actual IMK client's bundle identifier for the independent direct-input rule and focus/reentrancy checks; learned records do not retain it. Disabled, direct-input and secure clients neither record nor use the global profile. Client/settings revisions continue to reject stale candidates, clicks and automatic-confirmation tasks. `CandidateSelection.confirmationReason` compares against the displayed first candidate after font filtering/shortlisting; Space, number, mouse and navigation back to the first candidate stay neutral. First cells on later pages remain nonfirst. Punctuation's safeguards remain separate.

`ApplicationMemoryStore` performs actor-isolated I/O at the existing `SI/Personalization/application-memory-v1.json` path, with vocabulary-only schema 4, a 64 MiB file limit, owner-only permissions, atomic replacement and revision-ordered saves/deletion. Schemas 1–3 migrate atomically, stripping app identifiers/history and merging equal record identities: counts are summed with existing one-million caps, latest usage/base metadata is retained, and strength uses the maximum rather than stacking app bonuses. Schema-1/2 mixed default/correction evidence resets to neutral; schema-3 strength/corrections survive. No old schema supplies an exact-choice marker because it lacks a deliberate-selection timestamp. Age alone no longer invalidates retained records. Malformed/unsupported archives remain untouched; migration write failures propagate and pause loading. The retired `preferences-v1.json` archive is never decoded or imported and keeps its explicit deletion control.

Vocabulary retains at most 5,000 records; capacity eviction removes least recently used entries with identity tie-breaking. There is no timed expiry, decay or daily expiry task. Saves coalesce for 300 ms and flush on normal termination. Settings provide global search, Forget and global clear/archive erase under **Personal Learning**, with no application picker, pause or app discovery. Existing learning consent persists; old history flags never grant learning consent. The former App History draft/completion feature and previous-word pair learning remain absent. The separate Input History below does not provide candidates. No document, clipboard, URL or recipient is queried, and no keystroke-path disk access is introduced.

### Input History

`InputHistoryEntry` is a core value for one submitted composition: UUID event identity, timestamp, exact consumed source/output, optional language, mixed identity and commit reason. `SIInputController.apply` captures independent history consent/secure state and generation before calling the host's `insertText`, then rechecks the returned insertion/reentrancy boundary, client/direct-input policy and history consent before enqueueing the record. Candidate, literal, personal/verbatim, punctuation and automatic-confirmation submissions are eligible; empty commits, cancellation, marked edits and passthrough keys outside composition never create a row. Prefixes use `InputCommit.input`, excluding its remainder; actual SI-inserted suffixes are included in output. This captures SI's insertion contract, not a readback/acknowledgement of the host document. No host text is queried.

`InputHistorySettings` owns independent default-off `inputHistory.enabled`, a serialized task chain, bounded displayed pages, consent/storage/read generations and in-memory failed-write retry entries. Personal Learning and all retired consent keys cannot enable it. The key handler only creates a value and queues work. Save errors pause new recording and retain accepted failed entries for explicit retry; turning history off keeps previously accepted writes/data. Clear advances the storage/consent/read generations, stops recording until completion, discards pending retry records and serializes database removal after in-flight writes. Older queued inserts skip obsolete epochs. Entry deletion follows prior writes and removes that event from pending retries, so retry cannot resurrect it. Read generations reject late search/page results. Normal app launch prepares the history actor alongside other stores; termination awaits its queued work.

`InputHistoryStore` uses the system SQLite library, already linked by the shared engine, without a new dependency. Schema 1 lives separately at `SI/InputHistory/history-v1.sqlite3`, under 0700 directory/0600 file permissions with DELETE journaling. Each operation opens/closes its actor-confined connection; prepared SQL binds text with explicit UTF-8 lengths (including embedded NUL), and retrieval uses byte counts rather than C-string termination. UUID uniqueness makes retries idempotent while preserving repeated real submissions as distinct events. Append batches use transactions. There is no age/count eviction, full-archive rewrite or full in-memory load: newest-first pagination uses monotonic SQLite sequence cursors, returns at most 100 entries plus lookahead, and remains stable when newer events arrive or the wall clock moves backward. Search binds literal source/output substrings with ASCII case folding; no query/input text appears in error logs. Explicit row deletion uses secure_delete; explicit clear removes the database and journal/WAL/SHM sidecars, including corrupt/unsupported archives. This is not a guarantee of forensic erasure or backup deletion. Corrupt/unsupported opens preserve existing bytes. History is unencrypted and independent of learning/phrases/retired files, with no migration, ranking, completions, automatic training or network path. User-controlled export and offline preparation follow the separate workflow below.

### Sentence History

The independent `sentenceHistory.enabled` consent and `sentenceHistory.applications` allowlist control a second history settings instance and SQLite archive. A successful SI insert in an allowed client arms one later nonrepeated Return with an empty composition. Client/focus changes, Escape, direct input, observed secure input and consent-generation changes invalidate eligibility. `SentenceSnapshotReader` checks the unselected caret, no marked text, exact client length and returned UTF-16 range, stable client and caret, and a bounded, nonblank single line. The controller passes that Return to the app. The snapshot reflects the text before the app handles the key. App eligibility uses the IMK client's bundle identifier.

The separate archive reuses the history mutation queue and SQLite implementation, with a distinct database path and SQLite application ID. The export envelope is `si-sentence-history` version 1, scope `all_saved_sentences`. Its entries contain `type`, `sequence`, `id`, `created_at_unix` and `output`, with the same atomic publication, count and exact-byte checksum as Input History. The submission export format and receiver remain separate.

### Portable history export

`InputHistoryExportButton` opens `NSSavePanel` directly with one user-selected `.jsonl` destination and a private-data disclosure. Pending failed writes block export. Export success/error state is separate from recording/storage errors. The same action appears in the Settings section and paged history manager; search and current pages never limit the export.

`InputHistoryStore.export` streams one consistent SQLite read transaction in ascending native sequence order. The UTF-8 JSONL manifest declares format/version/scope/export time; each entry preserves original sequence, UUID, raw source/output, Unix time, language/mixed identity and reason. No normalization, aggregation, inferred labels, user/device metadata or automatic transfer is added. The live database/sidecars cannot be overwritten as export targets. Clear/delete after a snapshot does not erase its external copy.

Optional ASCII literal tasks require an explicit flag. No maintained train/validation/test sources, tensor preparation, runs, weights, remote storage or app history are changed by these commands. There is no seed-based content generation, Pinyin conversion, noise augmentation, source-manifest importer or automatic split path.

The default `llm/pinyin_to_text/data/pinyin-csv/` contains only explicit character and short-word sources. Its initial 2,021/73/69 train/validation/test pairs select earlier SI-authored vocabulary and add uniquely aligned character/reading pairs from training words only, excluding held-out input/output identities. This materialization is static and audited; runtime preparation never decomposes words. Sentence, English/mixed and typo data remain in the separately retained 50,000-pair collection with the 0.403B config. Neither that data nor existing weights are migrated implicitly. Limits are 48 source and 16 target tokens; generation remains unconstrained, with no copy branch. The corpus has limited character coverage, including held-out symbols absent from training outputs, so raw fallback and a lossless tokenizer do not establish learned conversion for those symbols.

The tokenizer fits training rows only and preserves unknown Unicode through UTF-8 byte fallback. Training reads train/validation only; explicit held-out candidate evaluation can additionally use a frozen external CSV benchmark's selected split. Checkpoints retain optimizer/RNG/batch position, and inference export omits training state. Prepared artifacts are ignored by Git; maintained CSVs are source files. Setup, prepare, train/resume, validation/test, inference/export and smoke scripts use the same isolated environment. Each ordinary stage script has defaults from `llm/scripts/defaults.sh` and invokes only its own task; `data.sh` aliases preparation and `run.sh` aliases training. They share explicit versioned data/run/report paths. Setup and separate candidate evaluation/export require their own invocations; training retains its periodic validation loss and checkpoints.

Old datasets, generator code, configs and smoke artifacts were removed. Previously trained weights/run records remain usable for inference/export, but their deleted prepared data and compatible runtime are not available for resume. New CSV training uses a new experiment with strict dataset/config/code identity checks.

The model's MPS path materializes full encoder/cross-attention masks to avoid a reproduced PyTorch 2.6 shape assertion, preserving padding and causal constraints. Numerical CPU/MPS comparisons and varied-length validation cover that repair. MPS activation checkpointing also explicitly replays per-layer accelerator RNG state: the pinned PyTorch version otherwise skips MPS RNG capture, producing different dropout masks and incorrect gradients during recomputation. The reusable recomputation context restores the caller's RNG on normal/early-stop exit; nonzero-dropout tests compare all gradients, RNG advancement and repeated backward against ordinary execution. CPU/CUDA retain their existing mask and checkpoint paths, and resume releases the loaded CPU checkpoint payload after state transfer. The fix changes code identity, so pre-fix runs remain inference artifacts and cannot silently resume across it. These checks do not establish representative conversion quality or host compatibility. Native candidate identity, enabled-language coexistence, spelling alignment, prefix commits and cancellation remain SI's core/controller contracts. See [the training guide](../llm/README.md).

## Extending language support

1. Add a stable language identifier and English display name to `InputLanguage`.
2. Implement a `CandidateProvider` with local, deterministic behavior and licensed data.
3. Register the provider in `CandidateEngine` and expose its enabled preference in Settings.
4. Test ambiguous sequences, disabled-language filtering, deterministic ranking, literal fallback, and composition resets.
5. Document dictionary provenance, performance characteristics, and limitations.

The new Chinese implementation and its current limits are described in the core section above and in [the pinned MSIME algorithm study](MSIME_ALGORITHM.md). English-only and Chinese/English lexical composition share the bounded search, with complete Chinese-word edges fetched from the maintained dictionary. Both lanes share the same public engine/session and existing personal-data controls.

The previous mixed decoder's guarded ASCII/CJK byte comparison and canonical Unicode fallback remain in `LexicalCompositionDecoder`. The measured performance figures recorded before this migration describe that previous implementation; they do not establish performance of the Swift MSIME adaptation. Exact output bytes are never normalized for committing.
